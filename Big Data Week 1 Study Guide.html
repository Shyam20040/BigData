1Big Data Fundamentals

DefinitionBig data is a collection of data sets so large and complex that it is difficult to process using on-hand database management tools or traditional data processing applications.

Challenges: capture, curation, storage, search, sharing, transfer, analysis and visualization.

Why bigger sets help: analysing one large set of related data reveals more than separate smaller sets of equal total size, allowing correlations to spot business trends, determine research quality, prevent diseases, link legal citations, combat crime and determine real-time traffic conditions.

Where the data comes from

Sources are people, machines and organizations (ubiquitous computing). More people carry data-generating devices (mobile phones, GPS, cameras). The old model had few companies generating data and everyone else consuming it; in the new model all of us both generate and consume data. About 80% of world data is unstructured.

The problem with traditional tools

RDBMS queries are insufficient for huge volumes; searching a trending topic with traditional tools would take so long the result is meaningless when computed. Big data therefore stores data in novel ways to make it accessible and adds methods to analyse it. Progress is no longer limited by collecting data, but by the ability to manage, analyse, summarize, visualize and discover knowledge in a timely, scalable way.

2Characteristics: the V's

IBM's 3 V's are Volume, Velocity and Variety; Value is the commonly added fourth. Many more V's have been proposed.

Big data analytics is more real-time than traditional data warehouses. Traditional DW architectures (e.g. Exadata, Teradata) are not well suited; shared-nothing, massively parallel, scale-out architectures are, and deliver value sooner.

Technology layers

  • Fast data: Hadoop, MapReduce, Vertica, Esper, kdb, Greenplum, Netezza, Teradata, ETL.
  • Big analytics: Hive, Mahout, SciPy, MATLAB, R, SPSS, SAS.
  • Deep insight: unsupervised learning, sentiment and social media analytics, predictive modeling, network analysis, visualization, simulation.

4Hadoop Core

DefinitionApache Hadoop is an open-source software framework for storage and large-scale processing of data sets on clusters of commodity hardware.

Origin: created by Doug Cutting and Mike Cafarella in 2005 to support the Nutch search engine; Cutting (then at Yahoo, now Cloudera chief architect) named it after his son's toy elephant. MapReduce and HDFS derive from Google's MapReduce and GFS.

Design principles

Move computation to data – not data to computation; started as batch framework.
Scalability – scale out across 100s–1000s of cheap commodity machines.
Reliability – hardware failure is the norm; failures handled automatically (fault tolerant).
Keep all data – schema-on-read; more data with simple algorithms often beats complex analytics on little data.

Four basic modules

ModuleRole
Hadoop CommonLibraries and utilities for other modules.
HDFSDistributed file system on commodity machines; very high aggregate bandwidth.

HDFS

Distributed, scalable, portable, Java file system. Stores files from gigabytes to petabytes across machines; reliability comes from replication across hosts (no RAID needed). Files are split into blocks spread over nodes.

  • NameNode (single per cluster): holds metadata (file name, replicas, e.g. /home/foo/data, 3); client sends metadata ops to it.
  • DataNodes: store blocks; client reads/writes directly, ideally from closest high-bandwidth rack; replicate between racks; send heartbeats.
  • Secondary NameNode assists the NameNode; the NameNode remains a single point of failure.

MapReduce

Users write a map function (key/value pair → intermediate key/value pairs) and a reduce function (merges all values for the same intermediate key). Google used it to index websites.

Hadoop 1 engine: a JobTracker (master) accepts client jobs and pushes work to TaskTrackers on slaves, keeping work close to data and balanced.

YARN (MapReduce 2.0)

Splits the JobTracker's two functions: resource management and job scheduling/monitoring. There is a global ResourceManager (with Scheduler, focused only on scheduling), per-node NodeManagers that launch Containers, and a per-application ApplicationMaster.

  • Scalable for very large clusters; fully compatible with existing MapReduce apps.
  • Improved utilization by capacity, guarantees, fairness and SLAs.
  • Supports other workloads (graph, iterative, machine learning, streaming) and multiple access engines. Yahoo uses YARN over 40,000 servers.

6Spark, NoSQL & Streaming

Apache Spark

Fast, general engine for large-scale processing, developed at UC Berkeley's AMPLab (2012) and donated to Apache; written in Scala. Uses in-memory primitives, up to 100× faster than disk-based two-stage MapReduce for some applications, and is ideal for iterative machine learning. Needs a cluster manager (standalone, YARN or Mesos) and storage (HDFS, Amazon S3).

Spark Streaming – scalable, fault-tolerant processing of live streams (Kafka, Flume, HDFS, sockets, Kinesis) as micro-batches (micro RDDs) → output to HDFS, DBs, dashboards.
MLlib – classification, regression, clustering, collaborative filtering, dimensionality reduction; pipelines, featurization, linear algebra, statistics.
GraphX – extends RDD with graph abstraction; directed multigraph with vertex/edge properties; PageRank, connected components, triangle count.

NoSQL (Not Only SQL)

SQL handles structured data well; NoSQL stores unstructured data with no fixed schema (each row can have its own columns) and performs better on massive data. Types: key-value, column-family, graph, document (examples: Cassandra, HBase, MongoDB).

  • Cassandra: highly scalable, distributed, high-performance; data replicated across machines for high availability and no single point of failure; nodes form a ring.
  • HBase: open source, from Google BigTable, Java; terabytes to petabytes.

Apache Kafka

Open-source distributed streaming platform (Scala/Java) built on a distributed commit log; handles trillions of events a day. Typical flow: data stream → Kafka → Spark Structured Streaming → console/memory/files.

7Quick Revision

Must remember
  • 3 V's + Value; Veracity = data in doubt; Valence = connectedness.
  • Big data lifecycle: OLTP → OLAP → RTAP.
  • Hadoop = HDFS + MapReduce + YARN + Common; move computation to data.
  • NameNode = metadata, single point of failure; DataNodes = blocks, replicated.
  • YARN: ResourceManager, NodeManager, ApplicationMaster, Containers.
  • Sqoop = structured import; Flume = logs; Pig = dataflow; Hive = SQL; Oozie = workflow; Zookeeper = coordination; HBase = NoSQL store.
  • Spark = in-memory, 100× faster; Streaming, MLlib, GraphX; Kafka = commit-log streaming.
