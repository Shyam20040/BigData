1Decision Trees

Decision tree ek acyclic graph hai jo decision nodes se banta hai: ek root, internal nodes (har node ek attribute test karta hai) aur leaves (predictions). Divide and conquer: data ko subsets mein split karo aur check karo ki har subset pure hai (all yes ya all no); pure ho toh stop, warna repeat. New sample us subset ke basis par predict hota hai jisme woh fall karta hai.

Example: will Sachin play cricket? (14 days: 9 Yes / 5 No)

Outlook9 yes / 5 no
→
Overcast4/0 pure → Yes
Sunny2/3 → Humidity par split: High 0/3 → No; Normal 2/0 → Yes
Rain3/2 → Wind par split: Weak 3/0 → Yes; Strong 0/2 → No

New day D15 (Rain, High humidity, Weak wind) → Rain → Wind = Weak → Yes (3/0).

Single decision tree – summary+ Handles feature interactions automatically (multiple splits se complex functions); + computationally scalable (many features wale very large data ke liye efficient algorithms, e.g. Spark clusters); + interpretable (splits aur leaves visualize); ? weak predictive power (overfitting/noise).

2ID3, Entropy & Information Gain

ID3 (Iterative Dichotomiser 3, Ross Quinlan 1986) dataset se decision tree generate karta hai; C4.5 (1993) ka precursor hai; CART (Breiman et al., 1984) statistics se aata hai.

Split(node, {examples}):
  1. A <- best attribute for splitting {examples}
  2. Decision attribute for this node <- A
  3. For each value of A, create a new child node
  4. Split training {examples} to child nodes
  5. For each child subset:
       if pure -> STOP
       else Split(child, subset)

Which attribute? Split ki "purity" measure karo. Pure set (4 yes/0 no) completely certain; 3 yes/3 no completely uncertain (50%). Measure symmetric hona chahiye (4 yes/0 no aur 0 yes/4 no equally pure), isliye P("yes"|set) nahi, entropy use hoti hai.

Entropy (bits)H(S) = −p(+) log2 p(+) − p(−) log2 p(−). Matlab: S ke item X ke positive ya negative hone ko batane ke required bits. Maximum 1 at p(+) = 1/2; pure set par 0 (p = 0 ya 1). Examples: 3 yes/3 no → 1; 4 yes/0 no → 0.
Information GainSplit ke baad entropy ka expected drop (attribute A aur class labels ki mutual information): Gain(S,A) = H(S) − Σv∈Values(A) (|Sv|/|S|) · H(Sv). Tree greedily top-down grow hota hai; har split maximum IG deta hai.

Worked example, Gain(S, Wind): H(S) = 0.94 (9 yes/5 no); H(Sweak) = 0.81 (6/2); H(Sstrong) = 1.0 (3/3). Gain = 0.94 − 8/14·0.81 − 6/14·1.0 = 0.049.

3Decision Trees for Regression

Training set Z = {(x1,y1),…} diya hai, jisme real targets yi hain. Aisa f(x) find karo jo Σ(f(xi) − yi)2 minimize kare. Node xk < t condition se ZL (yes, prediction aL) aur ZR (no, prediction aR) mein split hota hai.

  • No split: Squared error minimize karne wala ek number â predict karo; ye all targets ka average hai: â = (1/|Z|) Σyi. Impurity(Z) = mean squared error = (1/|Z|) Σ(â − yi)2.
  • Best split: k,t (aur leaf values, dono sides ke means âL, âR) choose karo, maximize: IG = Impurity(Z) − (|ZL|/|Z|·Impurity(ZL) + |ZR|/|Z|·Impurity(ZR)). Yani split se pehle ka error minus baad ka error; top se bottom repeat hota hai.
Stopping rules(1) Node depth maxDepth ke equal ho; (2) koi split minInfoGain se zyada gain na de; (3) koi split dono children mein kam se kam minInstancesPerNode training instances na de.

4Building Trees with MapReduce: PLANET

Problem: hundreds of attributes wala huge dataset – tree small/shallow (~10 levels, memory mein fit), par data ek machine ke liye too large. PLANET (Parallel Learner for Assembling Numerous Ensemble Trees, Panda et al., VLDB '09) MapReduce jobs ki sequence hai; setting: numerical attributes, numerical target (regression), binary splits Xj < v.

Mappermodel load; har data point ko uske leaf tak "drop"; har candidate split ke partial statistics rakhta hai
→
Reducerstatistics aggregate karke har node ka best split chunta hai
→
Masterhar MapReduce step mein tree ko one level grow karta hai
PLANET jobPurpose
Initialization (once, first)Splits ke liye consider hone wali attribute values identify.
FindBestSplit (many times)Data memory se too large ho toh best splits dhoondhna.
InMemoryBuild (once, last)Node ka data memory mein fit ho toh entire sub-tree grow.

Master sab monitor karta hai aur jobs run karta hai.

5Bootstrap & Bagging

BootstrapDataset Z ki replicas random sampling with replacement se banti hain; har pick independent. Naye dataset ka size same n, par kuch objects missing aur kuch repeat (e.g. original 1 2 3 4 5 → bootstrap 3 1 5 5 2).
Bagging (Bootstrap Aggregation)Kisi bhi algorithm ki predictions average karne ka general method (sirf trees nahi); prediction ka variance reduce karta hai.
Input: training set Z, B iterations, learning method M
For b = 1..B:
    draw bootstrap sample Z*b of size n
    apply M -> model f*b(x)
Return ensemble {f*1 ... f*B}
Regression:     f(x) = (1/B) Σ f*b(x)
Classification: majority vote of the B predictions

Why it works: training set khud random hota hai (user behavior, noisy physical measurements). Possible datasets par averaging models ke noisy/unstable parts hataati hai, stable/reliable parts reh jaate hain – bias-variance trade-off. Bagging almost kisi bhi method ko improve karta hai, lekin large data par very time-consuming ho sakta hai.

6Random Forest

DefinitionRandom Forest = de-correlated decision trees ki bagging. b = 1..B: bootstrap sample draw, de-correlated tree Tb grow, ensemble return. Regression: average; Classification: majority vote.
  • De-correlation: tree greedily top-down grow hota hai, par har split par sirf m randomly selected input variables (m ≤ p) candidates; har split information gain maximize karta hai. Recommended: classification m = √p; regression m = p/3; regression mein minInstancesPerNode = 5.
  • Experiment: m = √p wale de-correlated trees first ~20 trees tak worse, lekin eventually single DT ya all variables wale trees se better result par converge karte hain.
PropertySingle treeRandom ForestGradient Boosted Trees
Predictive powerPoorTree se better, GBDT se slightly worseBest general-purpose
InterpretabilityGoodLost (hundreds/thousands of trees)Poor
Parallelism–Trees independent → essentially parallel, distributed trainableSequential iterations

Quality order: Single DT < Random Forest < Gradient Boosted DT; predictive power badhne ke saath interpretability ghat-ti hai, yani hamesha trade-off hota hai.

7Gradient Boosted Decision Trees

Boosting many weak (base) classifiers ke outputs combine karke powerful ensemble banata hai; variants: AdaBoost, BrownBoost, LogitBoost, Gradient Boosting. Big data (many examples/features) mein complex model ke do tareeqe: complex model se start karke parameters fit (neural network), ya iteratively build, har step par simple model train (boosting).

Regression: f(x) = Σ h_m(x), each h_m a decision tree
f0(x) = (1/n) Σ y_i                      # initial mean label

For m = 1..M:
    ŷ_i = y_i − f_{m−1}(x_i)             # residuals
    fit tree h_m to targets ŷ_i          # auxiliary training set
    f_m(x) = f_{m−1}(x) + v · h_m(x)

Return f_M
v = regularization (learningRate), recommended ≤ 0.1
Link to optimizationGradient boosting gradient descent jaisa hai: gradient ke opposite direction mein small step size (v) se move karta hai. Ye functional space mein minimization hai.

Classification: labels y ∈ {0,1}; probabilistic model P(y=1|x) = 1 / (1 + exp(−f(x))), 0 < P < 1. Log-likelihood maximize: Q[f] = Σ log P(yi|xi) (ya loss L(yi, f(xi)) minimize); har tree gradients gi = dL/df par fit hota hai. Summary: GBDT classification/regression ka best general-purpose algorithm maana jaata hai.

9Cross-Validation in Spark ML

Cross-validation model quality assess karta hai aur ek family mein best model dhoondhta hai. Pipeline banao (yahan single stage: decision tree; generally preprocessing/string indexing bhi), ParamGridBuilder (e.g. maxDepth [1,2,4,5,6,7,8]; optional minInstancesPerNode ? zyada parameters se training slow), evaluator (accuracy) aur CrossValidator with numFolds=10 (5 ya 10 se kam folds nahi).

crossval = CrossValidator(estimator=pipeline, estimatorParamMaps=paramGrid,
                          evaluator=evaluator, numFolds=10)
cvModel = crossval.fit(inputDF2)      # trains/evaluates 10 times per setting
cvModel.avgMetrics                    # mean accuracy per maxDepth
cvModel.bestModel.stages[0]

Seven depths ke average accuracies: 0.892, 0.920, 0.942, 0.942, 0.946, 0.938, 0.936. Best model depth 6, 47 nodes; ise kisi bhi other dataset par prediction ke liye use kar sakte hain.

10Quick Revision

Must remember
  • Entropy H = −Σ p log2 p (0 pure, 1 for 50:50); Gain = H(S) − weighted child entropies; ID3 greedily max gain par split; Gain(S, Wind)=0.049.
  • Regression tree: leaf = mean; impurity = MSE; stop: maxDepth, minInfoGain, minInstancesPerNode.
  • PLANET: tree ke har level par one MapReduce step; Initialization ? FindBestSplit (repeat) ? InMemoryBuild.
  • Bootstrap = replacement ke saath sampling; bagging = average/majority vote, variance reduce.
  • Random forest = bagging + har split par p mein se random m features (classification ?p, regression p/3); trees independent ? parallel.
  • GBDT: f0=mean, residuals fit, f_m=f_{m?1}+v?h_m (v?0.1); functional space mein gradient descent.
  • Accuracy: Single DT < Random Forest < GBDT; interpretability mein reverse.
  • Spark ML: StringIndexer, 70/30 split, DecisionTree/GBT/RandomForest; ParamGrid ke saath 10-fold CrossValidator ? best depth 6.
