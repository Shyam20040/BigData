1Decision Trees

A decision tree ek acyclic graph hota hai jisme decision nodes hote hain: ek root, internal nodes (jo har baar kisi attribute ko test karte hain) aur leaves (predictions).

Divide and conquer: Data ko different subsets mein split karo, check karo ki har subset pure hai ya nahi (saare Yes ya saare No). Agar pure hai → stop. Agar pure nahi hai → process ko repeat karo.

Ek new sample ko us subset ke basis par predict kiya jata hai jisme woh fall karta hai.

Example: will Sachin play cricket? (14 days: 9 Yes / 5 No)

14 days ka data: 9 Yes / 5 No

Outlook

  • Overcast: 4/0 → pure → Yes
  • Sunny: 2/3 → split on Humidity
    • High: 0/3 → No
    • Normal: 2/0 → Yes
  • Rain: 3/2 → split on Wind
    • Weak: 3/0 → Yes
    • Strong: 0/2 → No

New day D15: Rain, High humidity, Weak wind

→ Rain → Wind = Weak → Yes (3/0)

Single Decision Tree — Summary: Advantages:

  • Feature interactions ko automatically handle karta hai (multiple splits ke saath complex functions).
  • Computationally scalable hai — bahut large data aur many features ke liye efficient algorithms use kar sakta hai, jaise Spark clusters par.
  • Interpretable hai — splits aur leaves ko visualize kiya ja sakta hai.

Disadvantage:

  • Predictive power weak ho sakti hai due to overfitting/noise.

2ID3, Entropy & Information Gain

ID3 (Iterative Dichotomiser 3, Ross Quinlan 1986) dataset se decision tree generate karta hai.

  • Ye C4.5 (1993) ka precursor hai.
  • CART (Breiman et al., 1984) statistics se aaya hai.

ID3 Split Procedure

Split(node, {examples}):
  1. A ← best attribute for splitting {examples}
  2. Decision attribute for this node ← A
  3. For each value of A, create a new child node
  4. Split training {examples} to child nodes
  5. For each child subset: if pure → STOP, else Split(child, subset)

Which Attribute?: Humein split ki "purity" measure karni hoti hai.

  • Ek pure set, jaise 4 yes / 0 no, completely certain hota hai.
  • 3 yes / 3 no completely uncertain hota hai (50%).

Measure symmetric hona chahiye:

4 yes / 0 no aur 0 yes / 4 no equally pure hone chahiye.

Isliye P("yes"|set) use nahi kar sakte → entropy use karte hain.

Entropy (bits): \[ H(S) = -p(+) \log_2 p(+) - p(-) \log_2 p(-) \]

Interpretation:

Entropy batata hai ki set S ke kisi item X ko positive ya negative batane ke liye kitne bits required hain.

  • Maximum entropy = 1, jab \(p(+) = \frac{1}{2}\)
  • Entropy = 0, jab set pure ho, yani \(p = 0\) ya \(1\)

Examples:

  • 3 yes / 3 no → Entropy = 1
  • 4 yes / 0 no → Entropy = 0

Information Gain: Information Gain split ke baad entropy mein hone wale expected drop ko measure karta hai.

Ye attribute A aur class labels ke beech mutual information ko represent karta hai.

\[ Gain(S,A) = H(S) - \sum_{v\in Values(A)} \frac{|S_v|}{|S|}\cdot H(S_v) \]

Tree greedily top-down grow hota hai, aur har split par woh attribute select hota hai jo maximum Information Gain (IG) deta hai.

Worked Example — Gain(S, Wind): \[ H(S) = 0.94 \]

for 9 yes / 5 no

\[ H(S_{weak}) = 0.81 \]

for 6/2

\[ H(S_{strong}) = 1.0 \]

for 3/3

Therefore:

\[ Gain = 0.94 - \frac{8}{14}\cdot0.81 - \frac{6}{14}\cdot1.0 = 0.049 \]

3Decision Trees for Regression

Training set:

\[ Z = \{(x_1,y_1),...\} \]

jahan targets \(y_i\) real-valued hain.

Goal hai ek function \(f(x)\) find karna jo:

\[ \sum(f(x_i)-y_i)^2 \]

ko minimize kare.

Ek node condition:

\[ x_k < t \]

ke basis par split hota hai:

  • \(Z_L\) → left side
  • \(Z_R\) → right side

No Split: Agar koi split nahi hai, to ek single number predict kiya jata hai jo squared error ko minimize karta hai.

Ye number all targets ka average hota hai:

\[ \hat{a} = \frac{1}{|Z|}\sum y_i \]

Impurity:

\[ Impurity(Z)=\frac{1}{|Z|} \sum(\hat{a}-y_i)^2 \]

Yani impurity = Mean Squared Error (MSE).

Best Split: Best split ke liye \(k,t\) aur leaf values select ki jati hain.

Leaf values each side ke means hote hain:

\[ \hat{a}_L,\hat{a}_R \]

Information Gain:

\[ IG = Impurity(Z) - \left( \frac{|Z_L|}{|Z|}Impurity(Z_L) + \frac{|Z_R|}{|Z|}Impurity(Z_R) \right) \]

Yani:

error before split − error after split

Ye process top-to-bottom repeatedly perform hota hai.

Stopping Rules

  1. Node depth = maxDepth
  2. Koi split minInfoGain se above information gain nahi deta.
  3. Koi split dono children mein kam se kam minInstancesPerNode training instances nahi de pata.

4Building Trees with MapReduce: PLANET

Problem: Dataset bahut huge hai aur usme hundreds of attributes hain.

Tree relatively small/shallow hota hai (~10 levels) aur memory mein fit ho sakta hai, lekin data ek single machine par fit nahi hota.

PLANET:

Parallel Learner for Assembling Numerous Ensemble Trees

(Panda et al., VLDB '09)

PLANET ek sequence of MapReduce jobs use karta hai.

Setting:

  • Numerical attributes
  • Numerical target (regression)
  • Binary splits:

\[ X_j < v \]

Mapper: Mapper:

  • Model load karta hai.
  • Har data point ko uske corresponding leaf tak "drop" karta hai.
  • Har candidate split ke liye partial statistics maintain karta hai.

↓

Reducer: Reducer:

  • Statistics ko aggregate karta hai.
  • Har node ke liye best split select karta hai.

↓

Master: Master:

  • Tree ko grow karta hai.
  • Har MapReduce step mein one level grow karta hai.

PLANET Jobs

PLANET JobPurpose
Initialization (once, first)Splits ke liye consider kiye jaane wale attribute values identify karta hai.
FindBestSplit (many times)Jab data memory se bahar ho, tab best splits find karta hai.
InMemoryBuild (once, last)Jab kisi node ka data memory mein fit ho jaye, tab complete sub-tree grow karta hai.

Master sab kuch monitor karta hai aur jobs run karta hai.

5Bootstrap & Bagging

Bootstrap: Bootstrap dataset Z ki replicas produce karta hai by random sampling with replacement.

Har pick independent hota hai.

New dataset ka size same n hota hai, lekin:

  • kuch objects missing ho sakte hain
  • kuch objects repeat ho sakte hain

Example:

Original:  1 2 3 4 5
Bootstrap: 3 1 5 5 2

Bagging (Bootstrap Aggregation): Bagging ek general method hai jo kisi bhi algorithm ki predictions ko average karta hai, sirf trees tak limited nahi hai.

Ye prediction ki variance reduce karta hai.

Input

  • Training set \(Z\)
  • \(B\) iterations
  • Learning method \(M\)

Process

For b = 1..B:
    draw bootstrap sample Z*b of size n
    apply M → model f*b(x)

Return ensemble {f*1 … f*B}

Regression: \[ f(x)=\frac{1}{B}\sum f_b^*(x) \]

Classification: B predictions ka majority vote liya jata hai.

Why It Works: Training set itself random hota hai — jaise user behavior ya noisy physical measurements.

Possible datasets par averaging karne se models ke noisy aur unstable parts remove ho jate hain, jabki stable aur reliable parts remain karte hain.

Ye bias-variance trade-off par based hai.

Bagging almost kisi bhi method ko improve kar sakta hai, lekin large data ke liye ye bahut time-consuming ho sakta hai.

6Random Forest

Definition

Random Forest = Bagging of de-correlated decision trees

For:

\[ b = 1..B \]

  • Bootstrap sample draw karo.
  • De-correlated tree \(T_b\) grow karo.
  • Ensemble return karo.

Regression: Predictions ka average.

Classification: Predictions ka majority vote.

De-correlation: Tree ko greedily top-down grow kiya jata hai.

Lekin har split par sirf m randomly selected input variables candidates hote hain:

\[ m \leq p \]

Har split maximum information gain karta hai.

Recommended Values: Inventors ke according:

  • Classification:

\[ m = \sqrt{p} \]

  • Regression:

\[ m = \frac{p}{3} \]

  • Regression ke liye:

\[ minInstancesPerNode = 5 \]

Experiment: \[ m=\sqrt{p} \]

(de-correlated trees) first approximately 20 trees ke liye worse perform karte hain, lekin eventually:

  • single Decision Tree se better result
  • all variables use karne wale trees se better result

par converge karte hain.

Comparison

PropertySingle TreeRandom ForestGradient Boosted Trees
Predictive powerPoorTree se better, GBDT se slightly worseBest general-purpose
InterpretabilityGoodLost (hundreds/thousands of trees)Poor
Parallelism–Trees independent → essentially parallel, distributed setting mein trainableSequential iterations

Order of Quality: \[ Single\ DT < Random\ Forest < Gradient\ Boosted\ DT \]

Yani predictive power badhti hai, lekin interpretability reduce hoti hai.

7Gradient Boosted Decision Trees

Boosting many weak/base classifiers ke outputs ko combine karke ek powerful ensemble banata hai.

Variants:

  • AdaBoost
  • BrownBoost
  • LogitBoost
  • Gradient Boosting

Big data mein many examples/features ke saath complex model banane ke do approaches hain:

  1. Complex model se start karo aur parameters fit karo — jaise neural network
  2. Iteratively build karo aur har step par ek simple model train karo — boosting

Regression: \[ f(x)=\sum h_m(x) \]

jahan har \(h_m\) ek decision tree hai.

Initial function:

\[ f_0(x)=\frac{1}{n}\sum y_i \]

Algorithm

For m = 1..M:
    ŷ_i = y_i − f_{m−1}(x_i)              # residuals
    fit tree h_m to targets ŷ_i (auxiliary training set)
    f_m(x) = f_{m−1}(x) + v · h_m(x)

Return f_M

where:

\[ v = regularization\ (learningRate) \]

Recommended:

\[ v \leq 0.1 \]

Link to Optimization: Gradient boosting gradient descent ki tarah work karta hai:

  • Gradient ke opposite direction mein move karta hai.
  • Small step size use karta hai — yahan v.
  • Ye functional space mein minimization karta hai.

Classification: Labels:

\[ y \in \{0,1\} \]

Probabilistic model:

\[ P(y=1|x)= \frac{1}{1+\exp(-f(x))} \]

where:

\[ 0<P<1 \]

Log-likelihood maximize kiya jata hai:

\[ Q[f]=\sum \log P(y_i|x_i) \]

Equivalently, loss minimize kiya jata hai:

\[ L(y_i,f(x_i)) \]

Har tree gradients ke according fit hota hai:

\[ g_i=\frac{dL}{df} \]

Summary: GBDT ko classification aur regression ke liye best general-purpose algorithm maana jata hai.
