1Machine Learning Basics

DefinitionMachine learning is the study of computer systems that learn from data without being explicitly programmed. Models learn a task by analysing many examples (e.g. recognising cats from many cat images, not step-by-step rules). The amount and quality of data strongly affect how well the model learns. ML discovers hidden patterns and trends, enabling data-driven decisions.

ML is interdisciplinary: maths and statistics, computer science and AI, plus domain knowledge (understanding the application, its data and how outcomes will be used) – essential for success.

Credit-card fraud detection – a purchase is compared with your history; very different purchases (big-ticket item, foreign location) are flagged.
Handwritten digit recognition – ATMs read cheque amounts; handwriting varies a lot.
Recommendations – "customers who bought this also bought…".
Others – targeted mobile ads, sentiment analysis, climate monitoring, crime-pattern detection, drug-effectiveness analysis.

Related terms

  • Data mining – finding patterns in databases/warehouses; same algorithms as ML plus data-access aspects.
  • Predictive analytics – analysing data to predict future outcomes (sales forecasting, customer behavior).
  • Data science – extracting meaning from data, usually big data, including collecting, storing and managing it; uses ML techniques.

Categories of techniques

TechniqueTypeGoal & examples
ClassificationSupervised, predictivePredict a category: weather (sunny/rainy/windy/cloudy), tumor benign/malignant, rain tomorrow, loan risk high/medium/low, tweet sentiment.
RegressionSupervised, predictivePredict a numeric value: stock price (but "will it rise or fall" is classification), product demand, test score, rainfall amount, drug effectiveness.
Cluster analysisUnsupervised, descriptiveGroup similar items: customer segmentation (seniors/adults/teens), topography types, tissue types, weather patterns, crime hot spots.
Association analysisUnsupervised, descriptiveRules on items/events occurring together: market-basket analysis (e.g. of transactions with milk: 71% bread, 43% eggs, 29% toilet paper), cross-selling CDs → money-market accounts, pages accessed together.

Supervised = target is provided (labeled data); unsupervised = target unknown (unlabeled data).

2The Machine Learning Process

Five steps, always carried out with a clear purpose (e.g. study purchasing behavior to raise sales revenue), and iterative – findings may send you back (e.g. quality problems in Prepare → return to Acquire).

1 Acquireidentify, collect, integrate data
→
2 Prepareexplore + pre-process
→
3 Analyzeselect technique, build, evaluate model
→
4 Reportcommunicate results
→
5 Actapply insights
  • Acquire: find all sources (files, databases, internet, mobile devices), collect and integrate; may need format conversion and alignment of time/spatial resolution. Data acquisition = gathering, filtering, cleaning before storage; a major big-data challenge.
  • Explore: look for correlations, trends, outliers. Summary statistics: mean, median (location), mode, range, standard deviation (spread) – e.g. negative or >100 ages are suspicious. Visualize: histogram (distribution, skew), line plot (trends), heat map (hot spots), scatter plot (correlation).
  • Pre-process: clean (missing values, duplicates, inconsistent/invalid data such as a six-digit zip, noise, outliers); feature selection (remove redundant/irrelevant features, e.g. sales tax vs price; combine or create features); feature transformation (scaling to a range, filtering/aggregation, dimensionality reduction).
  • Analyze: determine problem type, choose technique, build model, apply to new samples and evaluate.
  • Report: what and how to present; main results, insights, added value; even negative results are useful; visualizations plus backup tables.
  • Act: decide and implement action, consider effect on users, assess impact – which may start another cycle.

3Generalization & Overfitting

Error rate (misclassification rate) = incorrect predictions ÷ total samples. The model is built on training data and evaluated on separate test data (unseen during training). Training error = error on training data; test error = error on test data = generalization error (how well the model handles new data).

ConditionTraining errorTest errorCause
UnderfittingHighHighModel has not learned the data's structure
Good fitLowLowLearns the underlying trend
OverfittingVery lowHighModels the noise; model too complex (too many parameters for the samples)

Overfit models do not generalize; keep the model as simple as possible while still solving the mapping.

Overfitting in decision trees

A decision tree repeatedly splits data (e.g. Outlook → Sunny/Overcast/Rain → Humidity, Wind → Yes/No). Left unchecked it expands until it perfectly classifies training data, partitioning space by noise. Control complexity by limiting nodes:

MethodHow
Pre-pruningStop growth early with restrictive conditions (e.g. too few samples in a node; impurity improvement below a threshold). May stop prematurely.
Post-pruningGrow the full tree, then prune bottom-up, replacing a subtree with a leaf if generalization error improves or is unchanged. Usually better (uses the full tree) but more computationally expensive.

4Validation & Model Selection

A validation set (carved from the training data) tells us when to stop training. Plot error vs model complexity (e.g. number of nodes): training error keeps falling; validation error falls then rises – the rise marks overfitting, so stop where validation error is lowest. Using a validation set to choose among models of varying complexity is model selection (applies to any model type). Validation error also estimates generalization performance.

MethodDescription & notes
HoldoutReserve part of training data as validation set. Limits: less training data; misleading if distributions differ.
Repeated holdout (random subsampling)Repeat with a different random holdout set each time; average the validation errors.
K-fold cross-validationSplit data into k disjoint partitions; each iteration one partition validates, k times; every partition used exactly once; average error; pick model with smallest average. Very common; reduces variability of a single split.
Leave-one-out (LOOCV)k-fold with k = N; validation set has one sample; train on N−1.
Three datasetsTraining – fit model parameters; Validation – decide when to stop (avoid overfitting); Test – evaluate on new data. The test set must never be used to build or tune the model (nor in cross-validation) and stays untouched until the end. All sets must have the same class distribution (e.g. 70%/30% preserved), otherwise results mislead.

5Evaluation Metrics

For a yes/no class (e.g. "is this animal a mammal?"):

True labelPredicted: YesPredicted: No
YesTrue Positive (TP)False Negative (FN)
NoFalse Positive (FP)True Negative (TN)
MetricFormulaMeaning
Accuracy(TP+TN) / (TP+TN+FP+FN)Correct predictions ÷ total
Error rate1 − AccuracyIncorrect ÷ total
PrecisionTP / (TP+FP)Of samples predicted Yes, how many truly Yes – exactness
RecallTP / (TP+FN)Of true Yes samples, how many found – completeness
F-measureF1 = 2·P·R / (P+R)Combines precision and recall; F1 evenly weighted, F2 weights recall more, F0.5 weights precision more

Example (slide counts TP=3, FN=2, FP=1, TN=4): accuracy = 7/10 = 0.7, error rate = 1 − 0.7 = 0.3; computed from these: precision = 3/4 = 0.75, recall = 3/5 = 0.6.

7Cluster Analysis

Goal: organize similar items into groups (clusters) so each cluster can be analysed closely. Objective: intra-cluster differences minimized, inter-cluster differences maximized (samples in a cluster close together, clusters far apart), based on a similarity measure. Applications: customer segmentation by purchase history (sci-fi vs non-fiction vs children's books), weather patterns, grouping news into topics, crime hot spots.

Similarity measureDescription
Euclidean distanceStraight-line distance between points A and B.
Manhattan distancePath along axes only (horizontal + vertical steps).
Cosine similarityCosine of the angle between vectors: cos θ = xi·xq / (‖xi‖‖xq‖); inner product = Σ xi[j]·xq[j]. θ=0 → 1; θ=90° → 0; range −1 to 1 (0 to 1 for positive features like tf-idf). Distance = 1 − similarity. Not a proper distance metric; efficient for sparse vectors. Normalizing divides by the vector norm (e.g. norm √(1+25+9+1) = 6).

Distance measures may need normalized inputs so no variable dominates.

Key pointsClustering is unsupervised (no target); there is no single correct clustering (depends on use); clusters come without labels – interpretation and analysis are required.

Uses of cluster results

  • Data segmentation – analyse each segment for insight and targeted marketing.
  • Classify new data – assign a new sample to the closest cluster centre and use that cluster's (manually determined) label.
  • Labeled data – cluster samples become labeled training data for classification.
  • Anomaly detection – samples far from every centre are outliers needing further analysis (e.g. age 150).

8K-Means Algorithm

Select kinitial centroids
→
Classifyassign each sample to closest centroid
→
Recenternew centroid = mean of cluster
→
Repeatuntil stopping criterion
  • Initial centroids: final clusters are sensitive to them → run several times with different random starts and choose the best.
  • Evaluation – WSSE (within-cluster sum of squared error): sum over all clusters of squared distance between each sample and its centroid. Lower is numerically better, but it doesn't mean more "correct"; larger k always reduces WSSE.
  • Choosing k: visualization (scatter plots, dimensionality reduction); application-dependent (e.g. number of product categories or regions); data-driven – the elbow method: plot WSSE against k; the bend (e.g. k = 3) suggests k; may be ambiguous or give a range to try.
  • Stopping: no change to centroids, or number of samples changing clusters below a threshold (e.g. 1%).
  • Interpretation: each centroid is the mean of its cluster, a representative sample; compare centroid values (e.g. age) to see how clusters differ.
  • Summary: classic, simple, efficient; k must be specified; sensitive to initial centroids.

9Parallel K-Means with MapReduce

One iteration maps directly to MapReduce: Classify = Map (data-parallel over data points), Recenter = Reduce (data-parallel over centers).

PhaseOperation
MapGiven centers μ1..k and point xi: zi = argminj ‖μj − xi‖²; emit (zi, xi) – key = centroid id, value = data point.
ReduceFor cluster j receive its points; μj = (1/nj) Σi: zi=j xi; emit (j, μj) – sum and count, then sum/count.
reduce(j, x_in_cluster: [x1, x3, ...])
  sum = 0; count = 0
  for x in x_in_cluster: sum += x; count += 1
  emit(j, sum/count)

Iterative loop: new centers replace the old center version for the next pass until stopping (data points stored in HDFS). Practical issues: k-means needs an iterative MapReduce (not the standard formulation → Spark suits it); a mapper needs the data point and all centers (lots of data), so a better implementation has each mapper take many data points.

10Quick Revision

Must remember
  • ML = learning from data without explicit programming; supervised (classification, regression) vs unsupervised (clustering, association).
  • Process: Acquire → Prepare (explore, pre-process) → Analyze → Report → Act; iterative.
  • Overfitting = low training error, high test error; underfitting = both high; fight with pre/post-pruning and validation.
  • Holdout, repeated holdout, k-fold CV, LOOCV (k = N); test set is never touched during training.
  • Accuracy = (TP+TN)/all; precision = TP/(TP+FP); recall = TP/(TP+FN); F1 = 2PR/(P+R).
  • K-means: select centroids → classify → recenter; WSSE; elbow method; sensitive to initial centroids.
  • MapReduce k-means: Map = classify (emit centroid id, point); Reduce = average per centroid; needs iteration (Spark).
