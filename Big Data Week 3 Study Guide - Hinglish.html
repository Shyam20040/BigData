1Why Spark?

DefinitionSpark ek fast, expressive cluster computing system hai jo Apache Hadoop ke saath compatible hai. Isse originally UC Berkeley's AMPLab (2012) mein develop kiya gaya tha. Ye kisi bhi Hadoop-supported storage ke saath kaam kar sakta hai (HDFS, S3, SequenceFile, Avro…).

Efficiency in-memory computing primitives aur general computation graphs se aati hai; usability rich APIs (Java, Scala, Python; libraries mein R) aur interactive shell se aati hai. Claims: up to 100× faster, aur aksar 2–10× less code.

Limitations of MapReduce

  • Map outputs aur intermediate results fault tolerance ke liye HDFS mein save kiye jaate hain – ek expensive disk save jo performance ko kharab karta hai.
  • Iterative aur interactive applications ke liye costly hai; efficient data sharing nahi hoti.
  • Isi wajah se specialized frameworks aaye: Bulk Synchronous Processing (Pregel), iterative MapReduce.

Spark ideas: sirf map-reduce model tak limited nahi hai; system memory ka use karta hai, intermediate results ko disk par save karne se bachta hai, repetitive queries ke liye data cache karta hai (jaise machine learning), aur Hadoop ke saath compatible rehta hai.

Ways to run: local multicore (sirf ek library), EC2 scripts, private cluster via Mesos, YARN ya Standalone mode. Applications: Twitter spam classification, EM traffic prediction, K-means, ALS matrix factorization, Hive data par in-memory OLAP, SQL on Spark.

2RDDs & Fault Tolerance

Resilient Distributed DatasetEk immutable (read-only), partitioned collection of records jo cluster ke across failover hota hai, coarse-grained transformations (map, join…) ke through build hota hai, failure par automatically rebuild hota hai, aur memory mein cache kiya ja sakta hai (different storage levels; disk fallback).
TypeNatureExamples
TransformationsLazy; other RDDs se deterministic operations ke through naya RDD banata haimap, filter, flatMap, groupBy, join
ActionsValue return karta hai ya data export karta hai; execution trigger karta haicount, collect, take, reduce, save

Programmers partitioning aur persistence ko bhi control karte hain (RAM ya disk mein cache).

Fault tolerance by lineageRDDs us coarse-grained transformations ka log rakhte hain jinke through woh bane hain (e.g. HadoopRDD → FilteredRDD → MappedRDD). Lost partition ko sirf lineage se recompute kiya ja sakta hai – failure na ho to koi cost nahi.

Log-mining example: errors load karo, unhe cache() karo, phir repeated searches run karo. 1 TB data 5–7 s mein scan hota hai vs disk se 170 s.

lines = spark.textFile("hdfs://...")
errors = lines.filter(lambda s: s.startswith("ERROR"))
messages = errors.map(lambda s: s.split('	')[2])
messages.cache()
messages.filter(lambda s: "foo" in s).count()

3Scala Essentials

Scala JVM ke liye ek high-level, statically typed language hai; object-oriented + functional, speed Java ke comparable, with type inference aur full Java interoperability. Spark originally Scala mein likha gaya tha; interactive shell Scala aur Python mein available hain (standalone programs: koi bhi language). Java/Scala faster hote hain (static typing); Python numerics ke liye NumPy ke saath achha perform karta hai.

var x = 7        // mutable, inferred
val y = "hi"     // read-only
def square(x: Int): Int = x * x
var arr = new Array[Int](8)
var lst = List(1, 2, 3)
arr(5) = 7       // indexing with ()
list.map(_ + 2)          // List(3,4,5)
list.filter(_ % 2 == 1)  // List(1,3)
list.reduce(_ + _)       // 6
// (x: Int) => x + 2   full closure
// x => x + 2          inferred

List immutable hoti hai, isliye ye original value ko change nahi karti. Other Seq methods: flatMap (one-to-many), exists, forall, groupBy, sortBy.

5Job Execution

Spark application ke andar ek library ki tarah run hota hai (har app ke liye ek instance). Driver SparkContext hold karta hai; cluster manager (Standalone, Mesos, YARN) Workers/Executors allocate karta hai, jo tasks run karte hain aur cache hold karte hain; storage HDFS, HBase, S3, Cassandra, Avro ke liye Hadoop InputFormat ke through access hota hai.

RDD objects operator DAG build karte hain
→
DAGScheduler stages of tasks mein divide karta hai; each stage ko ready jaise submit karta hai
→
TaskScheduler tasks ko cluster manager ke through launch karta hai; failed/straggling tasks ko retry karta hai
→
Worker tasks execute karta hai; block manager blocks store/serve karta hai

DAG (Directed Acyclic Graph): source → transformations → RDDs → action; ye Spark ka execution plan hai aur executors par automatically scale hota hai. Scheduler general task graphs ko support karta hai, possible ho to pipeline functions use karta hai, cache-aware (reuse and locality) aur partitioning-aware hai to shuffle avoid kare. Shuffle = exchange, partition, sort across executors.

Job example: errors.cache() aur do filter(...).count() actions – first action workers par blocks load aur cache karta hai; second action cache reuse karta hai.

Build & submit: sbt package, phir spark-submit --master local --class GvaWeather target/…jar. Hadoop compatibility: InputFormat/OutputFormat reuse karta hai; filesystems ke liye textFile, any JobConf ke liye hadoopRDD.

6PageRank in Spark

Complex, multi-stage, iterative algorithm ka achha example hai jo in-memory caching se faayda uthata hai. Idea: kai pages se links ya high-rank page se links rank ko high karte hain.

Algorithm1. Har page ko rank 1 se start karo. 2. Har iteration mein page p apne neighbors ko rankp / |neighborsp| contribution deta hai. 3. Naya rank = 0.15 + 0.85 × Σ contributions.
Example: contributions 1 + 0.5 + 0.5 → 0.15 + 0.85 × 2 = 1.85. Ranks evolve 1.85, 0.58, 1.0, 0.58 → 1.31, 0.39, 1.72, 0.58 → final 1.44, 0.46, 1.37, 0.73.
val links = // RDD of (url, neighbors)
var ranks = // RDD of (url, rank)
for (i <- 1 to ITERATIONS) {
  val contribs = links.join(ranks).flatMap {
    case (url, (links, rank)) => links.map(dest => (dest, rank/links.size)) }
  ranks = contribs.reduceByKey(_ + _).mapValues(0.15 + 0.85 * _)
}

9Design of Key-Value Stores

Key-value abstraction: key → value (item number → item info; tweet id → tweet; account number → account). Yeh ek distributed dictionary hai (key ke through insert, lookup, delete, bilkul hash table ki tarah) aur P2P Distributed Hash Tables (DHTs) ki techniques ko reuse karta hai.

AspectRDBMS (e.g. MySQL)Key-value / NoSQL ("Not Only SQL")
StorageTables, poori row ek saath storedTables (Cassandra mein "column family", HBase mein "table", MongoDB mein "collection"); aam taur par ek column/column group saath stored hota hai
SchemaFixed, structured; primary/foreign keysSchemaless ho sakta hai; har row mein kuch columns missing ho sakte hain; foreign keys nahi; joins aksar supported nahi hote
QuerySQL, joinsget(key), put(key, value) aur extensions (Cassandra mein CQL); index tables bhi ho sakti hain
Aaj ke workloads ke liye RDBMS kyun mismatch karta haiData large aur unstructured hota hai (schema define karna mushkil); millions of clients random reads/writes karte hain, kabhi write-heavy bhi; foreign keys ki zarurat kam hoti hai aur joins infrequent hote hain (extra overhead).

Needs: speed, single point of failure (SPOF) se bachna, low TCO (total cost of operation/ownership), kam administrators, incremental scalability – scale out, scale up nahi.

Scale upZyada powerful machines se replace karna; traditional approach; price-curve ke sweet spot se upar cost-effective nahi; frequent replacement chahiye.
Scale outIncrementally aur COTS (Components Off The Shelf) machines add karna; sasta; newer machines phase in aur older machines phase out kar sakte hain; most data centers aur clouds mein use hota hai.

Column-oriented storage: poora database fetch kiye bina ek column ke andar range searches fast hoti hain – e.g. "blog_ids updated in the past month": last_updated column search karo aur sirf matching blog_id column fetch karo.

10Apache Cassandra: Key → Server Mapping

Cassandra ek distributed key-value store hai jo datacenter ke andar (aur multiple DCs ke across) run karne ke liye bana hai; Facebook mein design hua tha aur ab Apache project hai. Iske users mein IBM, Adobe, HP, eBay, Ericsson, Twitter, PBS Kids shamil hain; Netflix ise videos mein playback position track karne ke liye use karta hai.

Partitioner: key→server mapping define karta hai. Cassandra ring-based DHT without finger tables or routing use karta hai, aur har datacenter ke liye ek ring hoti hai. Example (m = 7, 2⁷ = 128 positions): nodes N0, N16, N32, N45, N80, N96, N112. Key K13 ke liye primary replica N16 hai aur backup replicas N32 aur N45 hain. Client read/write request coordinator ko bhejta hai, jo request replicas tak forward karta hai.

11Quick Revision

Must remember
  • Spark iterative/interactive jobs mein MapReduce ke disk-heavy intermediate results ki problem fix karta hai (up to 100×).
  • RDD = immutable, partitioned, lazily transformed; actions execution trigger karte hain; recovery lineage se hoti hai.
  • Transformations: map, filter, flatMap, reduceByKey, groupByKey, join, cogroup. Actions: count, collect, take, reduce, save.
  • Execution: Driver/SparkContext → cluster manager → executors; DAGScheduler (stages) → TaskScheduler (tasks).
  • PageRank: rank = 0.15 + 0.85 × Σ(rank/|neighbors|).
  • Libraries: SQL, Streaming, MLlib, GraphX.
  • Key-value stores: get/put, fixed schema nahi, column storage, scale out; Cassandra = ring partitioner with primary aur backup replicas.
