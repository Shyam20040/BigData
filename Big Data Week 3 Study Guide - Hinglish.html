1Why Spark?

Definition

Spark ek fast, expressive cluster computing system hai jo Apache Hadoop ke saath compatible hai. Isse originally UC Berkeley's AMPLab (2012) mein develop kiya gaya tha.

Ye Hadoop-supported kisi bhi storage ke saath work kar sakta hai, jaise HDFS, S3, SequenceFile, Avro…

Spark ki efficiency in-memory computing primitives aur general computation graphs se aati hai. Uski usability rich APIs ki wajah se hai — Java, Scala, Python aur libraries mein R — aur ek interactive shell bhi available hai.

Claims: up to 100× faster, aur often 2–10× less code.

Limitations of MapReduce

MapReduce mein Map outputs aur intermediate results HDFS par save kiye jaate hain taaki fault tolerance maintain ho sake. Lekin ye disk save expensive hota hai aur performance ko degrade karta hai.

  • Iterative aur interactive applications ke liye costly hai.
  • Efficient data sharing nahi hoti.
  • Isi wajah se specialized frameworks aaye, jaise Bulk Synchronous Processing (Pregel) aur iterative MapReduce.

Spark Ideas

Spark:

  • Sirf map-reduce model tak limited nahi hai.
  • System memory ka use karta hai.
  • Intermediate results ko repeatedly disk par save karne se avoid karta hai.
  • Repetitive queries ke liye data ko cache kar sakta hai, jaise machine learning.
  • Hadoop ke saath compatible rehta hai.

Ways to Run Spark

Spark ko different ways mein run kiya ja sakta hai:

  • Local multicore — sirf ek library ki tarah.
  • EC2 scripts
  • Private cluster via Mesos
  • YARN
  • Standalone mode

Applications

Spark ke applications mein:

  • Twitter spam classification
  • EM traffic prediction
  • K-means
  • ALS matrix factorization
  • Hive data par in-memory OLAP
  • SQL on Spark

2RDDs & Fault Tolerance

Resilient Distributed Dataset

RDD ek immutable (read-only), partitioned collection of records hai jo cluster ke across spread hota hai.

RDDs coarse-grained transformations jaise map, join etc. ke through build hote hain, failure hone par automatically rebuild kiye ja sakte hain aur memory mein cache bhi kiye ja sakte hain.

Different storage levels available hote hain, aur zarurat padne par disk fallback bhi ho sakta hai.

TypeNatureExamples
TransformationsLazy; deterministic operations ke through existing RDDs se new RDD create karte hainmap, filter, flatMap, groupBy, join
ActionsValue return karte hain ya data export karte hain; execution trigger karte haincount, collect, take, reduce, save

Programmers partitioning aur persistence ko bhi control kar sakte hain — data ko RAM ya disk mein cache karna.

Fault Tolerance by Lineage

RDDs un coarse-grained transformations ka record, yani lineage, maintain karte hain jinke through woh build hue hain.

Example:

HadoopRDD → FilteredRDD → MappedRDD

Agar koi partition lost ho jata hai, to us partition ko uski lineage se simply recompute kiya ja sakta hai.

Agar failure nahi hota, to is recomputation ki koi cost nahi hoti.

Log-Mining Example

Errors ko load karke cache() kiya ja sakta hai aur phir repeated searches run ki ja sakti hain.

1 TB data:

  • 5–7 s → cached/in-memory
  • 170 s → disk se

Code

lines = spark.textFile("hdfs://...")
errors = lines.filter(lambda s: s.startswith("ERROR"))
messages = errors.map(lambda s: s.split('\t')[2])
messages.cache()
messages.filter(lambda s: "foo" in s).count()

  • Workers/Executors → tasks run karte hain aur cache hold karte hain.
  • Storage ko Hadoop InputFormat ke through access kiya ja sakta hai:
    • HDFS
    • HBase
    • S3
    • Cassandra

6PageRank in Spark

PageRank ek complex, multi-stage aur iterative algorithm ka good example hai jo in-memory caching se benefit karta hai.

Idea

  • Many pages se links aana → high rank
  • High-rank page se link aana → high rank

Algorithm

  1. Har page ko initially rank 1 do.
  2. Har iteration mein page p apne neighbors ko:

rankp / |neighborsp|

rank contribute karta hai.

  1. New rank:

0.15 + 0.85 × Σ contributions

Example

Contributions:

1 + 0.5 + 0.5

Then:

0.15 + 0.85 × 2 = 1.85

Ranks evolve:

1.85, 0.58, 1.0, 0.58
        ↓
1.31, 0.39, 1.72, 0.58
        ↓
1.44, 0.46, 1.37, 0.73

Code

val links = // RDD of (url, neighbors)
var ranks = // RDD of (url, rank)

for (i <- 1 to ITERATIONS) {
  val contribs = links.join(ranks).flatMap {
    case (url, (links, rank)) =>
      links.map(dest => (dest, rank/links.size))
  }
  ranks = contribs.reduceByKey(_ + _).mapValues(0.15 + 0.85 * _)
}

9Design of Key-Value Stores

Key-Value Abstraction

Basic model:

key → value

Examples:

  • item number → item info
  • tweet ID → tweet
  • account number → account

Ye ek distributed dictionary ki tarah hai jisme key ke through:

  • insert
  • lookup
  • delete

kiya ja sakta hai.

Ye P2P Distributed Hash Tables (DHTs) se techniques reuse karta hai.

RDBMS vs Key-Value / NoSQL

AspectRDBMS (e.g. MySQL)Key-value / NoSQL ("Not Only SQL")
StorageTables, entire row stored togetherTables/column families; typically column/column group together stored hota hai
SchemaFixed, structured; primary/foreign keysMay be schemaless; columns row-wise missing ho sakte hain; no foreign keys; joins often unsupported
QuerySQL, joinsget(key), put(key, value) + extensions like CQL

Cassandra mein CQL use ho sakta hai aur index tables bhi ho sakti hain.

Why RDBMS Mismatches Today's Workloads

Aaj ke workloads mein:

  • Data large aur unstructured hota hai, isliye schema define karna difficult ho sakta hai.
  • Millions of clients random reads/writes karte hain.
  • Kabhi-kabhi workload write-heavy hota hai.
  • Foreign keys rarely required hote hain.
  • Joins infrequent hote hain, isliye relational overhead useful nahi hota.

Requirements

Need hai:

  • Speed
  • Single Point of Failure (SPOF) avoid karna
  • Low TCO (Total Cost of Operation/Ownership)
  • Fewer administrators
  • Incremental scalability
  • Scale out, not scale up

Scale Up

More powerful machines se existing system ko replace karna.

  • Traditional approach
  • Cost-effective nahi hota jab system price-curve sweet spot se above chala jaye.
  • Machines ko frequently replace karna padta hai.

Scale Out

Incrementally more COTS (Components Off The Shelf) machines add karna.

Benefits:

  • Cheaper
  • Newer machines ko gradually phase in kar sakte hain.
  • Older machines ko phase out kar sakte hain.
  • Most data centers aur clouds mein use hota hai.

Column-Oriented Storage

Column ke andar range searches fast hoti hain bina poori database ko fetch kiye.

Example:

"blog_ids updated in the past month"

→ last_updated column mein search karo aur sirf matching blog_id column fetch karo.

11Quick Revision

Must Remember

  • Spark MapReduce ke disk-heavy intermediate results ko avoid karta hai, especially iterative/interactive jobs mein; claims up to 100× faster.
  • RDD = immutable, partitioned aur lazily transformed; actions execution trigger karte hain; recovery lineage se hoti hai.
  • Transformations: map, filter, flatMap, reduceByKey, groupByKey, join, cogroup.
  • Actions: count, collect, take, reduce, save.
  • Execution: Driver/SparkContext → Cluster Manager → Executors → DAGScheduler (stages) → TaskScheduler (tasks).
  • PageRank: rank = 0.15 + 0.85 × Σ(rank/|neighbors|).
  • Libraries: SQL, Streaming, MLlib, GraphX.
  • Key-value stores: get/put, no fixed schema, column storage, scale out.
  • Cassandra: ring-based partitioner with primary aur backup replicas.
