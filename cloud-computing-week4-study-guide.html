1Meghamala: the IIT Kharagpur Private Cloud

Case studyMeghamala is an initiative of IIT Kharagpur to provide on-demand computational and storage resources to the institute's research community ("a one-stop solution to your computational needs: compute and storage with one click"). It is built on the OpenStack cloud platform and set up in the Computer and Informatics Centre (CIC). Hardware: blade servers, SAN storage and NAS.

Milestones: inauguration and workshop (April 2015) · MeghaData, a data-storage service, in beta (Aug 2015) · MegHadoop, a Hadoop cluster on Meghamala, available (March 2016).

3VM Lifecycle on OpenStack

CreationLaunch Instance: name, flavor, image, network
→
Accessconnect with a client such as X2Go
→
TerminationTerminate Instances, confirm
  • VM creation: in Launch Instance enter the instance name (Cloud_nptel_1), pick a flavor (m1.tiny or IITKGP_regular), a boot image (CentOS 6.5 GUI) and a network (net04_ext, net04). The instance passes through scheduling and building in Nova, then shows Active; a ping to its IP (10.4.2.38) succeeds, confirming it is reachable.
  • Accessing the VM: the user connects with the X2Go client using a session name, the VM's host IP, login (centos), SSH port 22 and session type XFCE, which gives a full CentOS desktop (file browser, Firefox).
  • Termination: choose Terminate Instances for the instance; a confirmation warns "This action cannot be undone"; the status shows Deleting, then "Scheduled termination of Instance".

5Demo: Python Web App on Azure

Azure Web Apps: a highly scalable, self-patching web hosting service. Prerequisites: install Git and Python. The workflow is: sign in at the Azure portal → open Cloud Shell (a free bash shell inside the portal) → prepare the sample locally → create cloud resources with the Azure CLI → deploy through Git.

Step 1: run the sample locally

git clone https://github.com/Azure-Samples/python-docs-hello-world
cd python-docs-hello-world
pip install flask
python main.py            # Running on http://127.0.0.1:5000/  → "Hello, World!"

Step 2: create the Azure resources (Cloud Shell)

StepCommandPurpose
Deployment useraz webapp deployment user set --user-name <username> --password <password>A deployment user is required for FTP and local-Git deployment
Resource groupaz group create --name myResourceGroup --location westeuropeA logical container for resources (web apps, databases, storage)
App Service planaz appservice plan create --name myAppServicePlan --resource-group myResourceGroup --sku FREEDefines location, size and features of the web-server farm: region, instance size (small/medium/large), scale count (1–20 instances), SKU (Free, Shared, Basic, Standard, Premium)
Web appaz webapp create --name <app> --resource-group myResourceGroup --plan myAppServicePlanProvides hosting space for the code and a URL (<app>.azurewebsites.net)
Python versionaz webapp config set --python-version 3.4 --name <app> --resource-group myResourceGroupUses the platform's default container for that version
Local Git deploymentaz webapp deployment source config-local-git --name <app> --resource-group myResourceGroupReturns the Git URL of the app (App Service also supports FTP, GitHub, Visual Studio Team Services)

Step 3: deploy and update

git remote add azure https://<deployuser>@<app>.scm.azurewebsites.net/<app>.git
git push azure master     # asks for the deployment password; Azure detects requirements.txt,
                          # the Python runtime and installs Flask
# browse to <app>.azurewebsites.net → Hello, World!

nano main.py              # change the returned text
git commit -am "updated output"
git push azure master     # redeploy; refresh the page to see the new message
Sample appfrom flask import Flask · app = Flask(__name__) · a route @app.route('/') returning a string · app.run(). After the change the page displays "Welcome to the NPTEL course on Cloud Computing!!".

8Demo 2: Web App on Google App Engine

  1. Open the Cloud Platform Console and create a new project (the project ID is derived from the name) with an App Engine application.
  2. Select the region to serve the app from (closer users see lower latency; it cannot be changed later), then choose the programming language (Node.js, Java, Python, PHP, Go, Ruby, .NET).
  3. Activate Cloud Shell and clone the Hello World sample repository (python-docs-samples).
  4. Every application needs app.yaml (configuration) and main.py (code):
# app.yaml
runtime: python27
api_version: 1
threadsafe: true
handlers:
- url: /.*
  script: main.app
  1. From the hello_world directory start the local development server with dev_appserver.py $PWD (default module at port 8080, admin server at 8000) and use Web preview to view the app ("Hello, World!"). The server stays running, watches source files and reloads on change; it can be shut down at any point.
  2. Edit main.py (a webapp2 request handler writing a plain-text response), reload the page to see the new message.
  3. Deploy: gcloud app deploy app.yaml --project <project-id> (shows the target project, service, version and URL, asks for confirmation, uploads files to Cloud Storage and updates the service).
  4. View: gcloud app browse (prints the URL https://<project>.appspot.com); logs can be streamed with gcloud app logs tail -s default.

Must remember
  • Meghamala: IIT Kharagpur's OpenStack private cloud (blade servers, SAN, NAS); VMs4U flavors regular/large/XLarge (2/4/8 vCPUs; 4/8/16 GB RAM); guest OS Ubuntu 14.04, CentOS 7, Fedora 20; VMs for academic use, up to 60 days.

  • Azure: resource group = logical container; App Service plan = region, size, scale count (1–20), SKU; deploy via local Git.
