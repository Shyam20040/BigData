2Parameter Server & Stale Synchronous Parallel

Parameter Server (PS): Parameter Server ek ML framework hai jo model ko multiple machines (PS shards) mein distribute karta hai.

Training state shards mein stored hoti hai aur asynchronous updates ke saath update hoti hai.

Iske do main operations hain:

  • Pull → model ke required parts ko query karna
  • Push → model ke parts ko update karna

Update equation:

\[ W_i \leftarrow W_i + \Delta \]

Examples:

  • Stochastic Gradient Descent (SGD)
  • Collapsed Gibbs sampling for topic models

Push updates ko addition ke through aggregate kiya jata hai.

Key-Value API for Workers

get(key) → value
add(key, delta)

Ye ek distributed shared memory ki tarah work karta hai.

Extensions:

  • Multiple keys → matrix
  • Multiple "channels"
  • Recent copies ka push/pull
  • Optional blocking
  • Clock-based blocking

Data-Parallel Learning: Data ko worker machines ke across split kiya jata hai.

  • Model ke different parts different servers par hote hain.
  • Workers apne required model parts ko fetch karte hain.

Flexible Framework: Parameter Server ka use different ML algorithms mein kiya ja sakta hai:

  • LDA (topic model)
  • Matrix Factorization (MF)
  • CNN
  • DNN

Examples:

  • Petuum
  • YahooLDA
  • DistBelief

Glint Spark mein parameter servers add karta hai.

Why not MapReduce for iterative ML?

MapReduce mein iterative ML ka cost high hota hai.

Training data ko repeatedly load karna padta hai aur stages ke beech output ko redundantly save karna padta hai.

The problem: networks are slow

Solution 1 — Cache Synchronization: Workers parameters ko cache karte hain aur model ko sirf sparse changes send karte hain.

Solution 2 — Asynchronous Execution: Asynchronous execution:

  • Barriers avoid karta hai.
  • Idle waiting nahi hoti.
  • More frequent coordination enable karta hai.

Lekin isme theoretical guarantees nahi hote, because network delays aur stragglers arbitrary ho sakte hain.

Stale Synchronous Parallel (SSP): Ek global clock \(t\) hota hai.

Worker ka get operation out-of-date ho sakta hai, lekin woh staleness bound \(s\) (τ) se zyada old nahi hona chahiye.

Fastest aur slowest workers ke clocks ka difference maximum s hona chahiye.

Agar fast worker bahut aage nikal jata hai, to woh block ho jata hai.

SSP:

  • BSP aur asynchronous execution ke beech interpolate karta hai.
  • Dono ko subsume karta hai.
  • BSP = staleness 0
  • Workers mostly apni own speed par run karte hain.
  • Parameters ko caching ke through efficiently implement kiya ja sakta hai.

Delayed SGD: \[ x_{t+1} = \arg\min_{x\in X} \left\| x-(x_t-\eta_t g_{t-\tau}) \right\| \]

Yani ek stale gradient ke saath gradient step, followed by projection onto the feasible space.

Consistency Matters: LDA ke 32 machines (256 cores) wale experiment mein suitable delay (SSP) ne strong consistency (BSP) ke comparison mein significant speed-up diya by reducing network waiting time.

SSP ne:

  • BSP se better perform kiya
  • Pure asynchronous execution se bhi better convergence diya.

PageRank: Larry Page aur Sergey Brin ne PageRank develop kiya.

  • Project started: 1995
  • Prototype: 1998
  • Google ka first algorithm for ranking search results.

Agar kisi page ko:

  • Bahut saare pages link karte hain, ya
  • High-rank page link karta hai,

to us page ka rank high hota hai.

PR(E) page E ka PageRank denote karta hai.

PageRank ko random surfer ke equivalent bhi dekha ja sakta hai.

Ranks stationary distribution form karte hain:

\[ x^=(x^)^TP \]

Basic PageRank: \[ PR(u)= \sum_{v\in\Gamma(u)} \frac{PR(v)}{L(v)} \]

where:

  • \(L(v)\) = page \(v\) ke outbound links ki number
  • \(\Gamma(u)\) = un pages ka set jo \(u\) ko link karte hain

PageRank with Damping Factor: Damping factor:

\[ d=0.85 \]

Formula:

\[ PR(p_i)= \frac{1-d}{N} + d\cdot \sum_{p_j\in\Gamma(p_i)} \frac{PR(p_j)}{L(p_j)} \]

where:

  • \(N\) = total pages
  • \(d=0.85\)

So:

\[ PR(p_i) = \frac{0.15}{N} + 0.85\cdot sum \]

Iteration: Initially:

\[ PR(p;0)=\frac{1}{N} \]

Then har step par PageRank update hota hai.

Stop kar sakte hain:

  • Fixed number of iterations ke baad, ya
  • Convergence ke baad:

\[ \sum |PR^{(t+1)}-PR^{(t)}|<\epsilon \]

Stationary Distribution Theorem: Unique stationary distribution exist karti hai agar:

  1. Har node se har node tak path available ho.
  2. Sabhi cycle lengths ka greatest common divisor = 1 ho.

Example: Four pages:

A, B, C, D

Initial PageRank:

\[ 0.25 \]

each.

Agar B, C aur D sirf A ko point karte hain:

\[ PR(A) = 0.25\cdot1+ 0.25\cdot1+ 0.25\cdot1 = 0.75 \]

Agar:

  • B → A ka outgoing weight = \(1/2\)
  • C → A ka outgoing weight = \(1\)
  • D → A ka outgoing weight = \(1/3\)

Then:

\[ PR(A) = 0.25 \left( \frac12+1+\frac13 \right) = 0.458 \]

Graph-Parallel Pattern: (Gonzalez et al., OSDI'12)

Ek vertex ki computation sirf uske neighbors par depend karti hai.

Pattern:

Gather: Neighbors se information gather karo.

↓

Apply: Vertex property par update apply karo.

↓

Scatter: Updated information neighbors ko send karo.

Examples: PageRank: \[ R[i] = 0.15+ \sum w_{ji}\cdot R[j] \]

Shortest Path: \[ D[i]=1+\min D[j] \]

Cluster Coefficient: \[ \frac{2\cdot \#Triangles[i]} {Degi} \]

Triangle counting local-community cohesiveness measure karta hai:

More triangles → stronger community

dono ko combine karta hai.

Graph computations ko relational algebra mein express kiya ja sakta hai.

Graph-system optimization ko reduce kiya jata hai:

  • Incremental materialized maintenance
