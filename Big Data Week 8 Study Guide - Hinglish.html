2Parameter Server & Stale Synchronous Parallel

Parameter Server (PS)

PS model ko multiple machines ke shards mein distribute karta hai; training state asynchronous updates ke saath store aur update hoti hai. Pull model ke parts fetch karta hai; Push updates bhejta hai. Wi ? Wi + ?; updates addition se aggregate hote hain (e.g. SGD, collapsed Gibbs sampling).

  • Worker API: get(key), add(key, delta); distributed shared memory jaisa. Multiple keys, channels, cached copies, optional/clock-based blocking support karta hai.
  • Data-parallel learning: data workers mein split hota hai; model shards alag servers par hote hain aur workers required parts fetch karte hain.
  • Algorithms: LDA, matrix factorization, CNN, DNN; examples Petuum, YahooLDA, DistBelief. Glint Spark mein parameter servers add karta hai.

Why not MapReduce for iterative ML?

Har iteration mein training data phir load hota hai aur stages ke beech output dobara save hota hai.

Network slow hone par

  • Cache synchronization: workers parameters cache karte hain aur sparse changes bhejte hain.
  • Asynchronous execution: barriers aur idle wait hata kar frequent coordination deta hai, lekin arbitrary delays/stragglers ke karan guarantees nahi hoti.
Stale Synchronous Parallel (SSP)Global clock t hota hai. Worker ka read stale ho sakta hai, par staleness bound s clocks se zyada nahi; fast worker limit cross kare toh block hota hai. SSP BSP aur async ke beech hai aur dono ko subsume karta hai; BSP mein staleness 0. Delayed SGD stale gradient use karke step leta hai, phir feasible space par projection karta hai.

LDA ke 32 machines (256 cores) wale experiment mein SSP ne BSP se network waiting kam karke speed-up diya, aur pure async se behtar convergence dikhayi.

3PageRank

Graphs social scale (1B vertices, 100B edges), web scale (50B, 1T) aur brain scale (100B, 100T) tak pahunchte hain. Web pages 1998 ke 150M se 2008 mein 1000B hue; link structure se importance ko objectively rate karna zaroori hai.

PageRankLarry Page aur Sergey Brin ne develop kiya (project 1995, prototype 1998); Google ka pehla search-ranking algorithm. Kai pages ya high-rank page se link milne par page ka rank badhta hai. Random surfer ke roop mein, ranks stationary distribution x* = (x*)TP banate hain.
  • Basic: PR(u) = ?v??(u) PR(v)/L(v); L(v) = v ke outgoing links, ?(u) = u ko link karne wale pages.
  • Damping: PR(p?) = (1?d)/N + d?? PR(p?)/L(p?), d = 0.85, N = pages ki sankhya.
  • Iteration: shuru mein har page ka rank 1/N; fixed iterations ya convergence ?|PR(t+1)?PR(t)| < ? par stop.
  • Unique stationary distribution: har node se har node tak path ho aur cycle lengths ka gcd 1 ho.

Example: A, B, C, D ka initial rank 0.25 hai. Agar B, C, D sirf A ko point karein toh PR(A)=0.75. Outgoing weights 1/2, 1, 1/3 hon toh PR(A)=0.25(1/2+1+1/3)=0.458.

6GraphX: Unified Approach & Design

GraphX ideaTables aur graphs ek hi physical data ke composable views hain. GraphX data-parallel aur graph-parallel execution ko jodta hai: distributed tables mein graphs encode karke graph computation relational algebra ke roop mein likhi ja sakti hai; optimization distributed joins aur incremental maintenance par based hai.
  • Property graph: Vertex Property Table (id ? property) aur Edge Property Table (source, destination, property).
  • Distributed layout: 2D vertex-cut heuristic ke saath Vertex, Routing aur Edge tables (RDDs) mein partition.
  • Operators: Spark RDD map/filter/groupBy/join/reduceByKey; graph views vertices, edges, triplets; reverse, subgraph, mapV, mapE, joinV, joinE, mrTriplets.
  • Triplets: vertex aur edge info ka join. mrTriplets edges par map karke destination ke hisab se reduce karta hai; e.g. har user ke oldest follower ki age nikalna.

9Quick Revision

Must remember
  • Parameter server: pull/push, W ? W + ?, get/add API, sharded model, async updates.
  • BSP barriers/staleness 0; async mein guarantee nahi; SSP staleness ko s clocks tak bound karta hai.
  • PageRank = (1?d)/N + d??PR/L, d=0.85; fixed iterations/convergence; unique stationary distribution ke liye strong connectivity aur cycle gcd=1.
  • MapReduce har iteration poora graph shuffle karta hai; Pregel supersteps, messages aur vote-to-halt use karta hai.
  • Graph-parallel = Gather ? Apply ? Scatter; Pregel push, GraphLab neighbor data pull karta hai.
  • GraphX tables + graphs unify karta hai: vertex/edge/routing tables, triplets, mrTriplets, 2D vertex cut; mirror cache, active-edge index, join elimination.
  • Flight case: 305 airports, 5366 routes, ATL degree 173; PageRank top ATL/DFW/ORD/MSP/SLC.
