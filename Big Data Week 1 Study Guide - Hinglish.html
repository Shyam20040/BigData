1Big Data Fundamentals

Definition: Big Data ek aisa collection of data sets hai jo itna large aur complex hota hai ki ise available database management tools ya traditional data processing applications se process karna difficult ho jata hai.

Challenges: Isme data ko capture, curate, store, search, share, transfer, analyse aur visualize karna major challenges hain.

Why bigger sets help: Ek large set of related data ko analyse karne se, same total size ke multiple smaller data sets ko separately analyse karne ke comparison mein zyada information reveal hoti hai. Isse hum correlations identify karke business trends spot, research quality determine, diseases prevent, legal citations link, crime combat aur real-time traffic conditions determine kar sakte hain.

Where the data comes from

Data ke sources people, machines aur organizations hote hain, jise ubiquitous computing kaha jata hai. Ab zyada log data-generating devices jaise mobile phones, GPS aur cameras carry karte hain.

Old model mein kuch hi companies data generate karti thi aur baaki sab log us data ko consume karte the. New model mein hum sab data generate bhi karte hain aur consume bhi karte hain.

World ke approximately 80% data is unstructured.

Scale – facts worth remembering

Walmart: 1 million transactions/hour

Facebook: 500 TB new data/day; 30+ PB user data; 40 billion photos

Flight: 6–8 hours mein 240 TB of data

Human genome: Originally 10 years → ab 1 week

CERN LHC: 15 PB per year

Earthscope: 3.8 million sq. miles mein 67 TB (seismic slips, Yellowstone magma)

Twitter: 12+ TB tweet data/day; 25+ TB logs/day (source slide)

Digital universe: 0.8 ZB (2009) → 35 ZB (2020), yani 44× rise

The problem with traditional tools

RDBMS queries huge volumes of data ke liye insufficient hain. For example, agar traditional tools se kisi trending topic ko search kiya jaye, toh result calculate hone mein itna long time lag sakta hai ki jab tak result mile, woh result practically meaningless ho chuka hoga.

Isliye Big Data data ko novel ways mein store karta hai, taaki data easily accessible ho, aur uske saath analysis ke methods bhi add karta hai.

Progress ab sirf data collect karne tak limited nahi hai, balki challenge ye hai ki data ko timely aur scalable way mein manage, analyse, summarize, visualize aur knowledge discover kiya ja sake.

2Characteristics: the V's

IBM ke 3 V's hain: Volume, Velocity aur Variety. Value ko commonly fourth V ke roop mein add kiya jata hai. Iske alawa bhi bahut saare V's propose kiye gaye hain.

Dealing with Volume: Big Data ko small information mein distill karo → parallel aur automated analysis karo → automation ke liye standardization chahiye → standardization ke liye Variety reduce karo, yani format, standards aur structure ko standardize karo.

3Evolution & Analytics

OLTP — 1968 hierarchical databases, 1970 relational databases Data at rest hota tha; history par reporting ki jaati thi.

→

OLAP — Data warehousing (1983, 1990) Current data ko analyse karke transactions ko improve kiya jata tha.

→

RTAP — Stream computing (2000, 2010) Data in motion hota hai; real-time response diya jata hai.

OLTP = Online Transaction Processing (DBMSs) OLAP = Online Analytical Processing (data warehousing) RTAP = Real-Time Analytics Processing (big data architecture and technology) Source: IBM.

Big Data analytics traditional data warehouses se zyada real-time hoti hai. Traditional DW architectures, jaise Exadata aur Teradata, iske liye well suited nahi hain. Iske instead shared-nothing, massively parallel aur scale-out architectures suitable hain, jo value ko sooner deliver karte hain.

Technology layers

  • Fast data: Hadoop, MapReduce, Vertica, Esper, kdb, Greenplum, Netezza, Teradata, ETL.
  • Big analytics: Hive, Mahout, SciPy, MATLAB, R, SPSS, SAS.
  • Deep insight: Unsupervised learning, sentiment and social media analytics, predictive modeling, network analysis, visualization aur simulation.

4Hadoop Core

Definition: Apache Hadoop ek open-source software framework hai jo commodity hardware ke clusters par data sets ko store aur large-scale processing karne ke liye use hota hai.

Origin: Hadoop ko Doug Cutting aur Mike Cafarella ne 2005 mein Nutch search engine ko support karne ke liye create kiya tha. Cutting us time Yahoo mein the aur ab Cloudera ke chief architect hain. Unhone iska naam apne son ke toy elephant ke naam par rakha. MapReduce aur HDFS, Google ke MapReduce aur GFS se derive hue hain.

Design principles

Move computation to data – Data ko computation ke paas move karne ke bajay computation ko data ke paas le jao. Hadoop initially ek batch framework ke roop mein start hua tha.

Scalability – Hundreds se thousands of cheap commodity machines ke across scale out kar sakta hai.

Reliability – Hardware failure normal hai; Hadoop failures ko automatically handle karta hai, yani system fault tolerant hai.

Keep all data – Schema-on-read approach use hoti hai. Zyada data ko simple algorithms ke saath process karna, kabhi-kabhi little data par complex analytics karne se better hota hai.

HDFS

HDFS ek distributed, scalable, portable Java file system hai. Ye gigabytes se lekar petabytes tak ki files ko multiple machines par store karta hai. Iski reliability hosts ke across replication se aati hai, isliye RAID ki need nahi hoti. Files ko blocks mein split karke different nodes par spread kiya jata hai.

  • NameNode (cluster mein single): File ka metadata hold karta hai, jaise file name aur replicas, e.g. /home/foo/data, 3. Client metadata operations ke liye NameNode ko request bhejta hai.
  • DataNodes: Actual blocks store karte hain. Client directly DataNodes se read/write karta hai, ideally closest high-bandwidth rack se. Blocks ko racks ke beech replicate kiya jata hai aur DataNodes heartbeats send karte hain.
  • Secondary NameNode: NameNode ko assist karta hai; lekin NameNode khud single point of failure rehta hai.

MapReduce

Users ek map function aur ek reduce function write karte hain.

  • Map: (key/value pair) → intermediate key/value pairs
  • Reduce: Same intermediate key ke saare values ko merge karta hai.

Google ne MapReduce ka use websites ko index karne ke liye kiya tha.

HDFS split input (k,v)

→

Map — (Key, value) emit karta hai

→

Shuffle & sort — values ko key ke according aggregate karta hai

→

Reduce — final (key, value) produce karta hai

Hadoop 1 engine: Ek JobTracker (master) client jobs ko accept karta tha aur slaves par TaskTrackers ko work assign karta tha. Ye work ko data ke close rakhne aur workload ko balance karne mein help karta tha.

YARN (MapReduce 2.0)

YARN ne JobTracker ke do functions ko separate kar diya:

  1. Resource management
  2. Job scheduling/monitoring

Isme ek global ResourceManager hota hai, jisme Scheduler hota hai jo mainly scheduling par focus karta hai. Har node par NodeManagers hote hain jo Containers launch karte hain, aur har application ke liye ek ApplicationMaster hota hai.

  • Very large clusters ke liye scalable hai aur existing MapReduce applications ke saath fully compatible hai.
  • Capacity, guarantees, fairness aur SLAs ke through resource utilization improve karta hai.
  • Other workloads jaise graph, iterative processing, machine learning aur streaming ko support karta hai, along with multiple access engines.
  • Yahoo 40,000+ servers par YARN use karta hai.

6Spark, NoSQL & Streaming

Apache Spark

Apache Spark ek fast, general-purpose engine hai jo large-scale data processing ke liye use hota hai. Isse UC Berkeley ke AMPLab mein 2012 mein develop kiya gaya aur baad mein Apache ko donate kar diya gaya. Ye Scala mein written hai.

Spark in-memory primitives ka use karta hai, isliye kuch applications mein disk-based two-stage MapReduce ke comparison mein up to 100× faster ho sakta hai. Ye especially iterative machine learning ke liye ideal hai.

Spark ko ek cluster manager ki need hoti hai, jaise Standalone, YARN ya Mesos, aur storage ke liye HDFS ya Amazon S3 use kar sakta hai.

Spark Streaming – Live streams ko scalable aur fault-tolerant way mein process karta hai. Ye Kafka, Flume, HDFS, sockets aur Kinesis jaise sources se data leta hai aur use micro-batches (micro RDDs) ke form mein process karta hai. Output ko HDFS, databases ya dashboards mein send kiya ja sakta hai.

MLlib – Machine learning ke liye use hota hai, jaise classification, regression, clustering, collaborative filtering aur dimensionality reduction. Isme pipelines, featurization, linear algebra aur statistics bhi included hain.

GraphX – RDD ko graph abstraction ke saath extend karta hai. Ye vertex aur edge properties ke saath directed multigraph support karta hai. Isme PageRank, connected components aur triangle count jaise operations available hain.

NoSQL (Not Only SQL)

SQL structured data ko handle karne ke liye achha hai, jabki NoSQL unstructured data ko store kar sakta hai jisme fixed schema nahi hota. Isme har row ke apne different columns ho sakte hain aur massive data par performance better ho sakti hai.

NoSQL ke main types hain:

  • Key-value
  • Column-family
  • Graph
  • Document

Examples: Cassandra, HBase, MongoDB

  • Cassandra: Highly scalable, distributed aur high-performance system hai. Data ko multiple machines par replicate karta hai, jisse high availability milti hai aur single point of failure nahi hota. Iske nodes ek ring form karte hain.
  • HBase: Open-source NoSQL database hai jo Google BigTable se derived hai aur Java mein written hai. Ye terabytes se petabytes tak ke data ko handle kar sakta hai.

Apache Kafka

Apache Kafka ek open-source distributed streaming platform hai jo Scala/Java mein built hai. Ye ek distributed commit log par based hai aur trillions of events per day handle kar sakta hai.

Typical flow:

Data stream → Kafka → Spark Structured Streaming → Console / Memory / Files

7Quick Revision

Must Remember

  • 3 V's + Value: Volume, Velocity, Variety + Value; Veracity = data jiske baare mein doubt ho; Valence = data ki connectedness.
  • Big Data Lifecycle: OLTP → OLAP → RTAP.
  • Hadoop: HDFS + MapReduce + YARN + Common; main principle hai computation ko data ke paas le jaana, na ki data ko computation ke paas.
  • NameNode = metadata manage karta hai aur single point of failure hota hai; DataNodes = data blocks store karte hain aur unki replication hoti hai.
  • YARN: ResourceManager, NodeManager, ApplicationMaster, Containers.
  • Sqoop = structured data import; Flume = logs; Pig = dataflow; Hive = SQL-like querying; Oozie = workflow; Zookeeper = coordination; HBase = NoSQL data store.
  • Spark = in-memory processing, kuch applications mein 100× faster; iske important components Streaming, MLlib, GraphX hain; Kafka = commit-log based streaming platform.
