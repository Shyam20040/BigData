1HDFS: Introduction & Design

Hadoop ek distributed file system provide karta hai aur MapReduce paradigm ka use karke very large data sets ko analyse karne ka framework bhi provide karta hai. Data aur computation ko thousands of hosts ke across partition kiya jata hai aur computations parallel run hoti hain, woh bhi data ke close.

Capacity, storage aur I/O bandwidth ko simply commodity servers add karke scale kiya ja sakta hai. Yahoo! ke clusters mein 25,000 servers tak hain jo 25 PB data store karte hain, aur largest cluster mein 3,500 servers hain. Yahoo! ne Hadoop ke core ka lagbhag 80% contribute kiya, including HDFS aur MapReduce.

Design Goals → Techniques

GoalTechnique
Thousands of nodes/disks → frequent failureData replication: same data ko different nodes par store karna

Files ko blocks mein split kiya jata hai aur ye blocks low-cost commodity hardware ke nodes ke local disks par distribute kiye jaate hain. Bahut saare disks ko aggregate karne se system ki performance aur scalability increase hoti hai.

2HDFS Architecture

Single NameNode (Master)

NameNode ek master node hota hai jo:

  • Namespace manage karta hai.
  • Client access ko regulate karta hai.
  • Track karta hai ki kaunse blocks kis DataNode par stored hain.
  • Metadata hold karta hai, jaise file name aur replicas.

Example: /home/foo/data, 3

Multiple DataNodes

Normally har node par ek DataNode hota hai, jo local storage use karta hai.

DataNodes:

  • Storage ko manage karte hain.
  • Client ki read/write requests serve karte hain.
  • NameNode ke instruction par blocks create, delete aur replicate karte hain.

3Hadoop 2.0 Improvements

HDFS Federation

HDFS Federation mein multiple NameNodes aur multiple namespaces hote hain.

Original design mein ek hi NameNode hota tha, lekin thousands of nodes aur billions of files hone par single NameNode bottleneck ban sakta hai.

Benefits:

  • Namespace scalability – namespaces ko independently scale kiya ja sakta hai.
  • Performance – load multiple NameNodes ke across distribute hota hai.
  • Isolation – different namespaces ko separately manage kiya ja sakta hai.

Data ko Block Pools mein store kiya jata hai.

  • Har NameNode/Namespace ke liye ek block pool hota hai.
  • Ye block pools sabhi common DataNodes ke across spread hote hain.
  • DataNodes multiple namespaces ke blocks store kar sakte hain.

High Availability

HDFS mein redundant NameNodes use kiye ja sakte hain, taaki NameNode failure ki situation mein system available rahe.

Heterogeneous / Archival Storage

HDFS different types ki storage ko support karta hai:

  • ARCHIVE
  • DISK
  • SSD
  • RAM_DISK

Architecture Flow

NN-1 / NS1 … NN-n / NS n → Multiple Namespaces

↓

Pool 1 … Pool n → Multiple Block Pools

↓

DataNode 1 … m → Common Storage

4Block Size & Small Files

Default block size 64 MB hota hai, lekin workload ke according ise often 128 MB tak increase kiya jata hai. Ye large files ke liye suitable hota hai.

Block Count = File Size ÷ Block Size

Example: 10 GB file → 10 × 1024 / 64 = 160 blocks

Block count ka impact:

  • NameNode Memory – har file/block ek object hota hai (~150 bytes each). 1 billion objects ≈ 300 GB memory le sakte hain. Agar 3× replication hai, to blocks ki count bhi 3× ho jaati hai.
  • Number of Map Tasks – kitne blocks process karne hain, uske according Map tasks ki number depend karti hai.
  • Network Load – DataNode checks ki frequency number of blocks ke proportional hoti hai.

Small-Files Problem

Agar 10 GB data ko 32 KB files mein divide kiya gaya, to:

10 GB → 327,680 map tasks

Isse:

  • Bahut bada task queue create hota hai.
  • Har task ke liye Java process ko start/stop karne ki latency hoti hai.
  • Disk I/O inefficient ho jata hai.

Solutions

Small-files problem ko solve karne ke liye:

  • Files ko merge/concatenate karna.
  • Sequence Files use karna.
  • HBase/Hive configuration use karna.
  • CombineFileInputFormat use karna.

DataNode: server/disk crash, corruption; network failure (jo multiple DataNodes ko affect kar sakta hai)NameNode ko periodic heartbeat aur block reports bheje jaate hain. 7MapReduce 1.0

MapReduce Hadoop ka execution engine hai. Hadoop 1.0 mein ye cluster resource management aur HDFS par data processing, dono handle karta hai.

JobTracker (Master)

JobTracker client se job receive karta hai, usse tasks mein break karta hai, slaves ko tasks allocate karta hai aur unki progress monitor karta hai.

Unit of execution = Job

TaskTracker (Each Slave)

TaskTracker local data par tasks run karta hai aur apni progress/results JobTracker ko report karta hai.

Master = JobTracker + NameNode Slaves = TaskTracker + DataNode

MapReduce 1.0 Process

1. Client submits job Client JobTracker ko job submit karta hai.

↓

2. JT asks NameNode for data location JobTracker, NameNode se data ki location poochta hai.

↓

3. JT tells TaskTrackers to run JobTracker TaskTrackers ko tasks execute karne ke instructions deta hai.

↓

4. Results stored on DataNode; NN informed Processing ke results DataNode par store hote hain aur NameNode ko inform kiya jata hai.

↓

5–6. TTs report to JT; JT tells client TaskTrackers apni progress/results JobTracker ko report karte hain, aur JobTracker client ko information deta hai.

↓

7. Client gets results from NN Client NameNode ke through results obtain karta hai.

Example

Maan lo 20,000 customer records hain. Inhe 5 chunks × 4,000 records mein split karke 5 nodes par distribute kiya jata hai.

Har node apne 4,000 records mein "Mumbai" ke customers ko find karta hai, aur parallel processing ke through complete dataset ko efficiently process kiya jata hai.

8MapReduce Paradigm

Definition

MapReduce ek programming model aur implementation hai jo large data sets ko process aur generate karne ke liye use hota hai.

User mainly do functions likhta hai:

  • Map: (key/value) → intermediate key/value pairs
  • Reduce: same intermediate key ke saare values ko merge karta hai.

Runtime automatically partitioning, scheduling, machine failures aur inter-machine communication handle karta hai. Isliye programmer ko parallel systems ka special experience hona zaroori nahi hai.

Why MapReduce?

MapReduce ka purpose hai 1000s of CPUs ko use karna without manually managing all the complexity.

Ye automatically handle karta hai:

  • Parallelization and distribution
  • Fault tolerance
  • I/O scheduling
  • Monitoring
  • Status updates

Map aur Reduce terms functional programming languages, especially Lisp, se aaye hain.

Example:

(map square '(1 2 3 4)) → (1 4 9 16)

Yahan records ko independently process kiya jata hai.

(reduce + '(1 4 9 16)) → 30

Yahan values ko combine kiya jata hai.

MapReduce Flow

Input Chunks / Records

↓

Map Parallel processing; (k, v) emit karta hai

↓

↓

Output

MapReduce Signatures

map(k, v) → list(k1, v1)

reduce(k1, list(v1)) → v2

  • Reduce values ko ek iterator ke through receive karta hai, isliye agar list memory se bahut badi ho tab bhi handle ki ja sakti hai.
  • Usually ek reduce call se 0 ya 1 output generate hota hai.
  • Har key exactly one reducer ko assign hoti hai.
  • Common method hash partitioning hai:

reduce# = hash(key) % number_of_reduce_tasks

Distributed File

Distributed file ko 16–64 MB chunks mein divide kiya jata hai.

  • Chunks ko 2–3× replicate kiya jata hai.
  • Replicas ko different racks par rakha jata hai.
  • Master (NameNode) metadata maintain karta hai.
  • Uske baad clients directly chunkservers/DataNodes se data access karte hain.

Map & Reduce Example

map(key, value):
    // key: document name; value: text
    for each word w in value:
        emit(w, 1)

reduce(key, values):
    // key: word; values: iterator of counts
    result = 0
    for each v in values:
        result += v
    emit(key, result)

Word Count Example

Input:

"see bob run"
"see spot throw"

Map:

bob   1
see   1
run   1
see   1
spot  1
throw 1

Shuffle & Sort: Same key ko group kiya jayega, isliye dono see values ek saath aa jayengi.

Reduce:

bob   1
run   1
see   2
spot  1
throw 1

So, see = 2 because "see" input mein 2 times appear hua.

9YARN Scheduler (Hadoop 2.x+)

YARN = Yet Another Resource Negotiator

YARN mein har server ko multiple containers ke form mein divide kiya jata hai. Har container ke paas fixed CPU + memory resources hote hain.

Example: Agar server mein 8 cores + 16 GB RAM hai, to ise 1 core + 2 GB ke containers mein divide kiya ja sakta hai.

ComponentRole
Global Resource Manager (RM)Scheduling handle karta hai.
Per-server Node Manager (NM)Daemon aur server-specific functions handle karta hai.
Per-application Application Master (AM)RM aur NMs ke saath containers negotiate karta hai aur apne job ke task failures detect karta hai.

Getting a Container

1. AM needs container Application Master ko ek container ki requirement hoti hai.

↓

2. RM allocates container Resource Manager available resources ke according kisi node par, maan lo Node B, container allocate karta hai.

↓

3. AM asks NodeManager to start task Application Master, NodeManager ko task start karne ke liye request karta hai.

↓

4. Container completion reported Task complete hone par container completion ki information report ki jaati hai.

  • 3 → [the, and, you]
  • 4 → [then, what, when]
  • 5 → [steve, where]
  • 8 → [savannah, research]

Reduce list ke size ko count karta hai:

3:3, 4:3, 5:2, 8:2

Inverted Index

Tweets:

  1. "I love pancakes for breakfast"
  2. "I dislike pancakes"

Finding Common Friends

Input:

A → B C D
B → A C D E
C → A B D E
D → A B C E
E → B C D

Ye data daily precompute karke store kiya jata hai.

Map: P → friends se sorted pair of P and each friend generate hota hai, aur saath mein P ki complete friend list emit hoti hai.

Example:

map(A → B C D):

(A B) → B C D
(A C) → B C D
(A D) → B C D

Phir same pair ke according data ko group kiya jata hai.

Example:

(A B) → (A C D E)(B C D)

Reduce dono friend lists ka intersection karta hai:

(A B) → (C D)

Final results:

AB → CD
AC → BD
AD → BC
BC → ADE
BD → ACE
BE → CD
CD → ABE
CE → BD
DE → BC

Jab D, B ki profile visit karta hai, to lookup:

(B D) → common friends A, C, E

Isliye B aur D ke common friends = A, C, E.

12Quick Revision

Must Remember

  • HDFS Goals: Fault tolerance, portability, large data aur high throughput → replication, write-once-read-many, computation ko data ke paas le jaana, relaxed POSIX requirements.
  • Block Size: 64 MB (128 MB common); 10 GB = 160 blocks; NameNode par approximately 150 bytes/object; small files → bahut zyada map tasks.
  • Federation: Many NameNodes + Block Pools; HA: redundant NameNodes; storage types = ARCHIVE, DISK, SSD, RAM_DISK.
  • Failure Handling: Heartbeat, re-replication, checksums, standby NameNode (manual failover default).
  • MR 1.0: JobTracker (master) + TaskTracker (slave), 7 steps; MR 2.0: YARN with ResourceManager (RM), NodeManager (NM), ApplicationMaster (AM) aur Containers.
  • MapReduce Flow: Map → Shuffle → Reduce; partitioning = hash(key) % reducers; distributed sort ke liye range partitioning use hoti hai.
