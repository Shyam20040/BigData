2Distributed Computing

Centralized vs distributed

Early computing ran on a single processor; uni-processor computing is centralized computing (terminals connected to a mainframe). In distributed computing several computers (workstations, hosts) are connected by a network link.

DefinitionDistributed computing is the field of computing science that studies distributed systems, and the use of distributed systems to solve computational problems.
Distributed system (Wikipedia): several autonomous computational entities, each with its own local memory, communicating by message passing. (Operating System Concepts): processors communicate through communication lines such as high-speed buses or telephone lines, and each has its own local memory.

Examples: the Internet, ATM (bank) machines, intranets/workgroups. The computing landscape will soon consist of ubiquitous network-connected devices.

Computers in a distributed system: workstations (used by end-users), server systems (provide resources and services), personal assistance devices (handheld computers on a wireless link).

Common properties

PropertyMeaning
Fault toleranceIf one or some nodes fail, the whole system still works (except performance drops); the status of each node must be checked.
Partial role of each nodeEach computer has only a limited, incomplete view of the system and may know only one part of the input.
Resource sharingUsers share resources in the system with other users.
Load sharingDispatching tasks to different nodes spreads load across the whole system.
Easy to expandAdding nodes should take little or (ideally) no time.
PerformanceParallel computing can be considered a subset of distributed computing.

Why distributed computing?

ReasonExplanationExample
Performance: computing intensiveTask consumes a lot of computing timeComputing the value of Pi by Monte Carlo simulation
Performance: data intensiveTask deals with a large amount or size of filesFacebook; LHC (Large Hadron Collider) experimental data processing
RobustnessNo SPOF (single point of failure): other nodes can execute the task of a failed node—

Distributed applications

Applications consisting of a set of processes distributed across a network of machines that work together as an ensemble to solve a common problem.

Client–server (past)Clients invoke individual servers (invocation → result). Resource management is centralized at the server.
Peer-to-peerPeer processes (Peer 1 … N) share objects among themselves. Represents a movement toward "truly" distributed applications.

When to use, and why it is needed

  • Share more than information: data, computing power and applications in a dynamic, multi-institutional environment (virtual organizations).
  • Efficient use of resources at many institutes; people from many institutions solve a common problem; join local communities.
  • Interaction with underlying layers must be transparent and seamless to the user.
  • Science today relies on computation, data analysis, data visualization and collaboration; simulation and modelling are more cost-effective than experiments; problems are more complex and need precise answers fast; data visualization is increasingly important; exploits under-utilized resources.
  • Users: reactor applications, natural-disaster detection and modelling, crystallography, material characterization, physics applications, weather forecasting.

4Cluster Computing

DefinitionA cluster is a type of parallel or distributed computer system consisting of a collection of interconnected stand-alone computers working together as a single integrated computing resource.

Components: multiple stand-alone computers (PCs, workstations or SMPs), operating systems, high-performance interconnects, middleware, parallel programming environments and applications.

Clusters improve speed and/or reliability over a single computer and are much more cost-effective than a single computer of comparable speed or reliability. In a typical cluster: a closer connection than a typical network, low-latency communication protocols, and looser coupling than SMP.

Types: High-availability (failover) · Load-balancing · Parallel/distributed processing
Building blocks: cluster nodes, cluster network, network characterization (nodes connected through a switch)

Key operational benefits

  • System availability: redundancy of hardware, OS and applications.
  • Hardware fault tolerance: redundancy for most components (e.g. disk RAID).
  • OS and application reliability: multiple copies of OS and applications.
  • Scalability: add servers, more clusters, or CPUs to an SMP as needed.
  • High performance: when running cluster-enabled programs.

5Utility Computing

DefinitionUtility computing is purely a concept which cloud computing practically implements. It is a service provisioning model in which a provider makes computing resources and infrastructure management available as needed and charges for specific usage rather than a flat rate. It has low or no initial cost; resources are essentially rented. The "utility" analogy is to services such as electrical power that meet fluctuating needs and charge on usage (pay-per-use).

It usually envisions some form of virtualization, so the storage or computing power available is much larger than a single time-sharing computer.

Key elements

Pay-for-use pricing business model
Data-center virtualization and provisioning
Solves the resource-utilization problem
Outsourcing
Web-services delivery
Automation

Payment models & risks

Payment models (same range as gas, electricity, telecom, water, TV): flat rate, tiered, subscription, metered, pay-as-you-go, standing charges. Pricing differs by scale, commitment and payment frequency, but the principle holds: price expresses the provider's cost of provision plus a profit margin.

Risks in a UC world: data backup, data security, partner competency, defining SLA, getting value from charge-back.

6Cloud Computing: NIST Definition & Characteristics

NIST definitionCloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g. networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.

Five essential characteristics

CharacteristicMeaning
On-demand self-serviceA consumer can unilaterally provision capabilities (server time, network storage) automatically, without human interaction with each provider.
Broad network accessCapabilities available over the network via standard mechanisms, supporting heterogeneous thin or thick clients (phones, tablets, laptops, workstations).
Resource poolingProvider resources are pooled to serve multiple consumers using a multi-tenant model; physical and virtual resources are dynamically assigned and reassigned by demand.
Rapid elasticityCapabilities are elastically provisioned and released (sometimes automatically) to scale outward and inward with demand; to the consumer they appear unlimited and available in any quantity at any time.
Measured serviceResource use is automatically controlled and optimized via a metering capability (storage, processing, bandwidth, active user accounts); usage is monitored, controlled and reported, giving transparency to provider and consumer.

Common characteristics

Resilient computing

Software as a Service (SaaS)

Software deployed over the Internet; a provider licenses an application on demand, by subscription, pay-as-you-go, or (increasingly) free when revenue comes from other streams such as advertising or user-list sales.

  • Characteristics: web access to commercial software; managed from a central location; "one-to-many" delivery; users need not handle upgrades and patches; APIs allow integration between different software.
  • Good fit: significant interplay between organization and outside world (email newsletter software); need for web/mobile access (mobile sales management); short-term need; demand spikes (tax/billing software). E.g. Salesforce CRM.
  • Poor fit: extremely fast real-time data processing; regulation forbids external hosting of data; an existing on-premise solution already meets all needs.

Platform as a Service (PaaS)

A computing platform for creating web applications quickly and easily, without the complexity of buying and maintaining the underlying software and infrastructure. Analogous to SaaS, except it is a platform for creating software, delivered over the web.

  • Characteristics: services to develop, test, deploy, host and maintain applications in one integrated environment; web-based UI creation tools; multi-tenant architecture; built-in scalability (load balancing, failover); integration with web services and databases via common standards; team-collaboration support; billing and subscription management tools.
  • Good fit: multiple developers or external parties in the development process; automated testing and deployment; agile development (iterative and incremental). E.g. Azure, Google App Engine.
  • Poor fit: application must be highly portable across hosts; proprietary languages would hinder later provider moves (vendor lock-in); performance needs customization of underlying hardware/software.

Infrastructure as a Service (IaaS)

Delivering infrastructure (servers, storage, network, operating systems) as an on-demand service. Instead of buying servers, software, data-center space or network equipment, clients buy them as a fully outsourced service.

  • Characteristics: resources distributed as a service; dynamic scaling; variable cost, utility pricing; generally multiple users on a single piece of hardware.
  • Good fit: volatile demand (spikes and troughs); new organizations without capital; rapid growth where scaling hardware is hard; pressure to limit capital expenditure and move to operating expenditure; trial/temporary needs.
  • Poor fit: compliance makes offshoring/outsourcing of storage and processing difficult; highest performance is needed and on-premise/dedicated infrastructure can deliver it.

XaaS: the generalization

XaaS"Anything/everything as a service": an increasing number of services delivered over the Internet rather than locally or on-site. Service-Oriented Infrastructure (SOI) + cloud computing realize XaaS; it is the essence of cloud computing.
Broad network access + resource pooling (cloud) + business-driven on-demand infrastructure + service orientation (SOI) = XaaS, which fulfils all four CSP requirements: increase productivity, end-user satisfaction, innovation and agility.

Virtualization

Virtual workspaceAn abstraction of an execution environment made dynamically available to authorized clients via well-defined protocols, with a resource quota (CPU, memory share) and software configuration (e.g. OS). Implemented on virtual machines (VMs): an abstraction of a physical host. A hypervisor (VMM) intercepts and emulates VM instructions and manages VMs (VMware, Xen, KVM). An infrastructure API provides plug-ins to hardware.

VM technology lets multiple VMs run on a single physical machine. Para-virtualization (e.g. Xen) performs very close to raw physical performance.

Advantages of VMs: run operating systems where physical hardware is unavailable; easier to create and back up machines; software testing on "clean" installs; emulate more machines than physically available; time-share lightly loaded systems on one host; debug by suspending and resuming; easy migration; run legacy systems.

10Cloud Economics & Business Drivers

Main reason for interest: public clouds can significantly reduce IT costs. To the end user the cloud gives the illusion of potentially infinite capacity, scaling rapidly and paying only for consumed resources. In contrast, private data centers must provision for peak capacity, giving a low average utilization of 5–20%.

The cloud's raw hourly cost is higher (ratio 1.88), but after accounting for efficiency, power/cooling and management it is cheaper overall (in-house costs 1.58× more). (Source: Enterprise Cloud Computing, Gautam Shroff.)

Benefits of public cloud for the end user

  • High utilization and high scalability; no separate hardware procurement, power cost, or IT infrastructure administration/maintenance.
  • User-friendly SLAs: high availability (~99%) with compensation if the SLA is missed.
  • Rent the cloud to develop and test prototypes before major technology investment.
  • Portability standards from the Cloud Computing Interoperability Forum and Open Cloud Consortium; e.g. Amazon EC2 and Eucalyptus share the same API.
  • Software start-ups benefit by renting infrastructure instead of buying, since their future is uncertain.

Benefits of private cloud

  • One server with 12 cores and 12 GB RAM costs far less than 12 servers with 1 core and 1 GB each.
  • Data confidentiality is preserved; VMs are cheaper and faster to provision than actual machines.

PaaS vs IaaS economics, and SaaS benefits

PaaS vs IaaSFor a 24×7 web app with unpredictable transaction volume: IaaS needs a minimal number of servers provisioned at all times. PaaS deployment costs nothing up front; cost follows usage, and the platform scales automatically. PaaS also removes user handling of scaling/load balancing, offers web-based IDEs, eases migration from development to production, and avoids separate IDE licences.
SaaS benefitsUsers subscribe to web applications instead of buying and licensing software (e.g. free Google Docs instead of buying Microsoft Word). Enterprises use SaaS CRM instead of buying servers and installing CRM software and databases.

Drivers (survey data in slides): top ranked factors were reduced infrastructure cost (67%), flexibility (54%) and scalability (41%). IT industry rated easy/fast deployment and pay-per-use highest. SMBs expect cloud use for email, backup, voice, web conferencing and file sharing to roughly double in 2–3 years. Typical uses: backup, CRM/ERP, development and testing, archiving, data analysis, handling demand spikes, batch jobs, collaboration, video conferencing.

↔

Layered view of cloud services

Presentation layer (consumer interfaces, API) → business processes (BPaaS) → services (SaaS, PaaS, IaaS) → service components → operational systems (compute, network, storage, facilities). Cross-cutting concerns: integration, quality of service, information, governance.

Network Function Virtualization (NFV)

Definition (ETSI)NFV transforms how network operators architect networks by evolving standard IT virtualization to consolidate many network equipment types onto industry-standard high-volume servers, switches and storage (in data centres, network nodes or end-user premises). Network functions are implemented in software that runs on standard server hardware and can be moved to or instantiated in various network locations as required, without installing new equipment.

13Quick Revision

Must remember
  • Paradigm order: distributed → grid → cluster → utility → cloud. Utility computing is the concept; cloud is its practical implementation.
  • Distributed system: autonomous nodes, local memory, message passing; no SPOF. Grid: single system image, virtual organizations; 5 types (computational, data, collaboration, network, utility). Cluster: stand-alone computers acting as one; 3 types (high-availability, load-balancing, parallel).
  • NIST essential characteristics (5): on-demand self-service, broad network access, resource pooling (multi-tenant), rapid elasticity, measured service.
  • Service models: SaaS (use the app) · PaaS (deploy your app) · IaaS (provision fundamental resources). XaaS adds BPaaS, SECaaS, DaaS, MaaS, CaaS, IDaaS, BaaS and others.
  • Deployment models: private, community, public, hybrid (cloud bursting).
  • Virtualization: hypervisor/VMM (Xen, VMware, KVM) runs multiple VMs on one host.
  • Economics: private data centers average 5–20% utilization; the cloud is cheaper per effective hour ($0.86 vs $1.36; ratio 1.58); PaaS costs nothing until used.
  • Disadvantages: constant Internet, speed, limited features, security and data loss, lack of standard APIs, HPC limits, vendor lock-in.
  • Elasticity: scale-up (bigger box) vs scale-out (more units); scale-out for large scenarios.
  • Three-tier: presentation, logic, data. Cloud vs client–server: complex service models, load balanced, infinitely scalable, virtualization at the core.
  • Networking: VLAN, VPN, OSI layers split between consumer and provider; NFV replaces dedicated appliances with software on standard servers.
